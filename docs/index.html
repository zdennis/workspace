workspace

A macOS CLI for managing tmuxinator-based development workspaces in iTerm2 — launch, focus, kill and relaunch projects with automatic window positioning.

Requirements

  • macOS (uses AppleScript and Accessibility APIs)
  • Ruby 3.4 or 4.x (both tested on CI)
  • iTerm2
  • tmux and tmuxinator
  • window-tool and git
  • ascii-banner (optional, banner in the launcher pane)

A headless launch needs only Ruby, tmux, tmuxinator and git — no macOS, iTerm2 or window-tool.

brew install tmux tmuxinator gh
brew install zdennis/bin/window-tool
brew install zdennis/bin/ascii-banner

Install

Clone the repo and put bin/ on your PATH:

git clone https://github.com/zdennis/workspace.git ~/source/opensource/workspace
export PATH="$HOME/source/opensource/workspace/bin:$PATH"

Add the export line to your ~/.zshrc to keep it across shells.

Set up

Create the config directories and install the agent hooks:

workspace init

Then verify everything is in place:

workspace doctor

doctor checks for the required tools and prints install instructions for anything missing.

First run

The first AppleScript call asks whether your terminal may control iTerm2 — click OK. Also grant your terminal (and window-tool) access under System Settings → Privacy & Security → Accessibility. Without it, workspace launch and focus can't position windows.

Then add a project and launch it:

cd ~/source/my-project
workspace add
workspace launch my-project

Run a workflow

A workflow is an ordered list of steps — research, plan, implement, verify — run by the agent in a workspace's pane, with gates, checks and locks. rpiv is the built-in preset: research, plan (behind an approve gate), implement, verify.

workspace workflow run rpiv --input task="PROJ-101 invoice PDF export"

Add --dry-run first to preview what would start. For work no one watches, the recommended preset is rpiv-auto-approve-v2:

workspace workflow start rpiv-auto-approve-v2 --prompt "add a retry to the uploader"

See where a run stands with workspace workflow status, and every workflow with workspace workflow list.

The shape of a workflow

workspace workflow graph rpiv draws any workflow as Mermaid, DOT, JSON or ASCII. The rpiv preset, in ASCII:

        |
        v
      +----------+
      | Research |
      +----------+
        |
        v
      +------+
   +->| Plan |
   |  +------+
   |    |
   |    v
   |  +===========+
   +--| Plan gate |  reject (or --to an earlier step)

        |

|       |
|       v

+-----| Verify |  fail: max 3
      +--------+
        |
        v
      (End)

Add your own workflows

Beyond the presets that ship, workspace reads workflow definitions from a local directory or a GitHub repository. Point the workflows.sources config key at either — a local path:

workspace config set workflows.sources '~/workflows'

or a GitHub directory (a URL with ref, or shorthand owner/repo/path):

workspace config set workflows.sources 'https://github.com/acme/workflows/tree/main/presets'
workspace config set workflows.sources 'acme/workflows/presets, ~/workflows'

Then fetch and check them:

workspace workflow install

Every .yml file in the source is checked, GitHub sources are cached under the state directory, and the report names what is new, changed or gone. Run it again to update. Your own files in ~/.config/workspace/workflows/ always win over sources; sources win over the presets.

Tips

  • Everything speaks JSON. Every command takes --json and prints a stable, versioned document — the same words a person reads and a machine parses. workspace capabilities --json reports the version and feature set, so a script or agent can ask what this install can do.
  • It ships with skills for your coding agents. Run workspace skills install and it links one skill per subject into each harness it finds (Claude Code, Codex, Pi, OpenCode):
    • workspace — router and ground rules for the CLI: workspaces, worktrees, agents in tmux panes, everyday verbs.
    • workspace-lifecycle — create, restore and end workspaces and worktrees: start, launch, promote, prune.
    • workspace-workflow — start and follow workflow runs: go, workflow start, workflow status.
    • workspace-agent-run — talk to another workspace's agent: message, ping, nudge, run a command and wait.
    • workspace-inbox — leave to-dos and questions for the person, answer an agent's ask.
    • workspace-template — choose, check and apply the tmuxinator template sets behind pane layouts.
  • Running workspaces can talk to each other. agent-run send messages, pings or nudges another workspace's agent pane, queues for when it is idle, or runs a command in it and waits — agent to agent, not just person to agent.
  • There is a companion UI. workspace-ui is a lightweight desktop app for managing workspace projects; the CLI's ui open builds its links.
  • From ticket to running workflow in one command. workspace go PROJ-101 (or a PR URL, issue, branch or plain text) picks the workflow for the ref and starts it in a new or existing workspace.
  • Reboots are not fatal. workspace restore --all brings back the agent panes a reboot or tmux restart took, typing each session's resume line; workflow recover restarts mid-turn workflow steps.
  • Let the sweep keep runs moving. workspace workflow sweep --install sets up a launchd entry that recovers stalled or timed-out steps on a schedule, so unattended runs do not wait for you to notice.
  • Clean up merged work with one verb. workspace prune removes worktree-backed projects whose GitHub PR is closed or merged; workspace doctor --fix repairs most setup problems it finds.
