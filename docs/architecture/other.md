# Other

Everything else: config, git, library, skills, rename, ticket and pull-request commands, the core layer, and spec tooling. Full per-file detail, moved verbatim from `.claude/CLAUDE.md`; the one-line index there links here.

- `lib/workspace/config.rb` — Path constants and configuration (including `workflow_event_errors_path`, the log of workflow history lines that could not be written)
- `lib/workspace/commands/notes.rb` — `notes dir`: the one answer to where a workspace's notes are, through `NotesDir`; `--create` makes the directory and lists it in `info/exclude`; `workspace ui open notes [WS] [--path REL]` sends the person to the Notes view, or one note, through `Commands::Ui` (`workspace-ui://notes/<ws>[/<rel>]`; `--path` is checked by `NotePath.resolve`, refused as `invalid_note_path`)
- `lib/workspace/commands/promote.rb` — `promote [BRANCH] [--name WS] [--dry-run] [--json]`: moves a main checkout's changes and branch commits into a new `.worktrees/<branch>` through `CheckoutMove`, makes it a workspace through `start` (no launch, plan or spine), carries notes through `NotesCarry`, then makes the spine and plan asked for and not carried; refuses `agent_working` (the caller's `$TMUX_PANE` aside); writes `workspace_promoted`; docs in `docs/README.promote.md`
- `lib/workspace/checkout_move.rb` — The git half of `promote`: checks (`plan`, read-only), one tagged stash pinned to `refs/workspace/promote/<id>`, switch, `worktree add`, `stash apply --index` checked against trees recorded before; a failure is undone in reverse (`move_failed`) or kept under the ref (`move_incomplete`); INT, TERM and HUP wait for the step under way through `DeferredSignals`
- `lib/workspace/notes_carry.rb` — Moves `IMPLEMENTATION_PLAN.md` and `spine/` (the old ones renamed `.moved-<time>`) and copies each `--carry-note` into the new notes directory, never over a file; problems are warnings; `.clash?` says whether a copy would land over an existing file (`rename`'s notes check)
- `lib/library/play/promote.md` — The `promote` pack: tell the person what moves, run promote, seed the spine and plan, write `HANDOFF.md`, start the agent, stop
- `lib/workspace/core/` — The lowest layer: the shared rules and tables every other layer may read, and nothing in it depends on anything outside `core/`. Fifteen files: `template_variables`, `logger`, `config_schema`, `config_layering`, `config_resolver`, `error_codes`, `duration`, `agent_provider`, `workspace_lineage`, `workspace_name`, `id_patterns`, `file_lock`, `atomic_file`, `locked_json_file`, `agent_protocol` (each described on its own line below)
- `lib/workspace/core/id_patterns.rb` — `IdPatterns`: the name rules shared across sub-systems (`LIBRARY_NAME`, `WORKFLOW_ID`, `WORKFLOW_ID_RULE`), the fallback ids `STDIN_ID` and `FILE_ID` a definition read from stdin or a path gets when nothing names it, and the two readers behind them (`claimed_id` reads a string `id:` out of a definition's text, `file_id` reads the file's name); read by `LibraryStore`, `WorkflowDefinition`, `WorkflowCatalog`, `Commands::Workflow`, `config_schema` and their other readers
- `lib/workspace/core/config_schema.rb` — The one table of config keys: scope, settable, default, value parser, restart flag, doc text; readers, `config set/get/unset` and the docs take their key lists and checks from it
- `lib/workspace/notes_dir.rb` — The one resolver for where a workspace's notes go: its own `notes.dir`, else the directory the project's `notes.default_dir` rule computes, else (a linked worktree) the main checkout workspace's effective notes dir plus the sanitized branch (`tmp/workspace-notes` in the checkout when unset); `config show --json` reports it as `effective_path`; `#path_for(template:, worktree:, root:, workspace:, branch:)` computes the rule's directory for names not yet in use (`rename`'s notes target); `Commands::Notes#info` returns the answer as a Hash (`dir` prints it) and `#files_inside_worktree` counts the files `kill` and `finish` would delete
- `lib/workspace/config_schema_docs.rb` — Renders the schema into the generated blocks of `docs/README.config.md`; `script/generate-config-docs [--check]` runs it, and a spec fails on drift
- `lib/workspace/state.rb` — JSON-persisted session state
- `lib/workspace/git.rb` — Git and worktree operations; `#path_of`, `#current_branch_name` and `#head_name` (`rev-parse --abbrev-ref HEAD`) are the small reads other classes take as a `git:` seam
- `lib/workspace/name_migration.rb` — Renames a mixed-case workspace (and its worktree workspaces) to lowercase before its agentd starts, under the startup lock: tmux session, configs, run files, state dir, inbox files, state key, marker, tmuxinator config last (held back while any step failed); a failed step is a warning in the daemon log; writes `workspace_renamed`. The steps live in `WorkspaceStoreRename`; `NameMigration` keeps the lowercase decision and the locks. `EnsureAgent` calls `#call` under its startup lock (keyed on the lowercase name); `launch` and a foreground `agentd` call `#call_locked`; `#with_locks(*names)` holds the startup locks of several names (sorted) for `rename`, raising `LockUnavailable`; `#hold_if_possible(name)` is one name's lock, the block running without it when the lock can't be taken, for `remove`, `kill` and `prune` (their `locks:`), which delete a config inside it so `template apply` never writes one back
- `lib/workspace/core/workspace_name.rb` — The workspace name rules: pure class methods `SEPARATOR` (`.worktree-`), `.split` (project and suffix at the first separator, nil without one; same as `WorkspaceLineage.split_worktree_name`, whose callers move later), `.worktree?`, `.project_of`, `.join` (lowercased), `.mixed_case?`, `.normalize`, `.same?`; and the instance that settles a name: `#for_input(name)` is for a name a person typed (the exact name in any case wins, else the one config whose part after `.worktree-` equals it, ignoring case; several are `ambiguous_workspace`; an active workspace with no config keeps its name); `#match` and `#resolve` stay exact, since they also settle names from paths and detection; the CLI's `given_name` is its only caller of `#for_input`
- `lib/workspace/which.rb` — Shared default PATH lookup for injectable `which:` collaborators
- `lib/workspace/doctor.rb` — Dependency checking; the `templates` row (the resolved tmuxinator set, its validation, `template import` for a legacy edited copy) and the `template-current` rows from `TemplateStatus`, whose `--fix` runs `TemplateApply` without force before the agent pane fix; warns on a paused plan whose owner pane is working and on a `[~]` task in a workspace with no session; checks the configured command's program on PATH; reports each tmuxinator config whose agent pane runs another command than `agent.commands.<kind>` (`agent-pane-command`), and `--fix` rewrites that pane through `ProjectConfig#rewrite_agent_pane` after a `FileBackup`; checks the skill links (`skills-<harness>` rows) through `Commands::Skills#health`, and `--fix` repairs them through `#repair`; `review_orphans:` lists left-over review windows (`workflow-review-window-orphaned`, warn, `--fix` leaves them) and `tmux:` warns on `renumber-windows on`, global or any session's own (`tmux-renumber-windows`); `sweep_schedule:` and `sweep_last_path:` (with `clock:`) feed the `workflow-sweep` row, which shows the last full pass from `sweep-last.json` and warns when it is missing, over two intervals old, unreadable, or the installed plist is out of date
- `lib/workspace/project_config.rb` — Tmuxinator config generation; `DEFAULT_CLAUDE_PANE` is the flagged Claude Code line; a template holding `{{AGENT_COMMAND}}` is filled by `#agent_pane_value(kind, workspace)` (claude: the default line with the configured program swapped in; another kind: the bare command; through `yaml_item`) and skips `with_agent_kind`, and `template_claude_line` answers `DEFAULT_CLAUDE_PANE` for it, while a template with a literal `claude ...` line keeps the search and rewrite; `#render(kind, inputs, template_text)` is the pure render, and `create`/`create_worktree` render the template `Library#tmuxinator_template` resolves (`library:`, a callable answering the Library, since the Library reads `ProjectConfig`; `check_agent_kind!`, `agent_pane_command` and `template_claude_line` read the resolved worktree template) and write through the injected `writer:` (a `TmuxinatorConfigWriter`), recording the set's name (`legacy` for an edited installed copy), the render inputs plus `agent_command`, the agent pane text written
- `lib/workspace/project_catalog.rb` — Groups workspaces into projects (main checkout + worktrees) by the realpath of each checkout's git common dir, read from `.git` files; backs `projects`
- `lib/workspace/project_groups.rb` — Groups of repositories (`group:<slug>` ids), one hand-editable file each at `~/.config/workspace/groups/<slug>.yml`; members keyed by the realpath of the git common dir, at most one group per repository, a gone repository reads `exists: false`; writes under one flock through a temp file and rename; `#group_for_project` is the lookup by project id. `Commands::Groups` is `projects group create|add|list`; `projects stop`/`kill` refuse a `group:` id. `ProjectCatalog` knows nothing of groups
- `lib/workspace/osascript_runner.rb` — Runs one AppleScript through `osascript` with a 5s limit; past it the process group is stopped and the answer is empty with `timed_out`; `ITerm` and `WindowManager#close_window` go through it, and `UiAppProbe` through a second runner set to `osascript -l JavaScript`
- `lib/workspace/ui_app_probe.rb` — The one read-only question to macOS for `ui status`: a frozen JXA script (no input, opens nothing) asks which app would take a `workspace-ui://` link, with its `WorkspaceUILinkRevision`, and which copies are running; `#call` answers `Answer(handler, running, problem)`, and no answer is a `problem`, never an error
- `lib/workspace/commands/ui.rb` — `ui open [VIEW] [WORKSPACE]` builds a `workspace-ui://` link and hands it to `open` (no view means `task`); `ui status [--json]` turns the probe's answer into a read document, reporting a link revision only when the bundle that declares it is the app that would take the link (else null with a `links.reason`), always exit 0
- `lib/workspace/iterm.rb` — iTerm2 session/pane lifecycle (AppleScript); `#last_call_timed_out?` says iTerm2 did not answer, which `stop` turns into a warning
- `lib/workspace/focus_config.rb` — Reads the global `focus.chain` (default `focus + center + dim --opacity 0.5 --duration 3`) into the steps after the first `focus`, as token arrays split on `+`; a value `config set` would refuse, or an unreadable global file, gives the default's steps and a warning, so a bad config never stops `focus`
- `lib/workspace/shell_init.rb` — `ShellInit.text(shell)`: the fixed text `shell-init zsh|bash` prints for an rc file (single-quoted heredocs, nothing interpolated): `wf` (`workflow start` with the default `rpiv` or `WORKSPACE_WF_DEFAULT`), `wfp` (fzf or numbered picker), and the completion for `workspace` and `wf`; docs in `docs/README.shell-init.md`
- `lib/workspace/window_manager.rb` — iTerm2 window operations: find, focus, position, close; `#run_focus_steps` runs a chain's window-tool steps in order, `dim` and `highlight` detached (counted started after 0.25s), the first failure stopping the rest and returned as a `StepFailure`
- `lib/workspace/window_liveness.rb` — Whether iTerm still has each tracked workspace's recorded window (one `live_window_ids` call, none when all are headless); nil for headless or when the list can't be read; backs `window_alive` in `status --json`, `list --liveness --json` and `cleanup`
- `lib/workspace/window_layout.rb` — Window positioning math
- `lib/workspace/core/error_codes.rb` — Registry of the stable error `code` values, mirrored in `docs/README.json.md`
- `lib/workspace/library_store.rb` — The files of one library scope (`<kind>/<name>.md`, or a `skill/<name>/` directory holding `SKILL.md`, or a `spine`/`template` directory (`README.md` optional; `files` listed); a copy or a symlink), written through a temp file or directory and rename; `renamer:` moves the finished temp entry into place (default `File.rename`) `LibraryStore.files_of(path)` and `.tree_sha(path)` list and digest a template folder's regular files without links or dotfiles (what `template export`, `import` and `restore` copy and compare).
- `lib/workspace/library.rb` — Resolves a library `REF` across scopes; `#stores` is the one lookup order (project, global, then the built-in store `lib/library/`); `#pack` looks an instruction pack up built-in first; `#play` checks the play `start --play`/`launch --play` point the agent at; `#copyable` checks a `start --agent`/`--skill` entry; `#tmuxinator_template(kind, workspace:)` is the tmuxinator template a new config renders from: the set `TmuxinatorTemplateConfig` names (project of the workspace, global, built-in; `unknown_template` with `details.kind: tmuxinator`), that set's `project.yml` or `worktree.yml`, or, with no key set at any layer, an installed copy in `~/.config/tmuxinator/` that `LegacyTmuxinatorTemplates.edited?` says was edited (name `legacy`; decided once per kind per instance)
- `lib/workspace/recipe_file.rb` — Parses and checks a `recipe` library entry (YAML: `plays`, `packs`, `agents`, `skills`, `agent_kind`, `prompt`, `description`, `workflow`, `workflow_inputs`; `workflow` excludes the list fields and `prompt`, and an input is a String, Integer or boolean turned into a string), listing every problem under `invalid_recipe`; `Library#recipe` reads one, `start --recipe` fills in the flags not given (a recipe with a `workflow` goes to `workflow start` instead and refuses flags it can't use as `recipe_workflow_conflict`), and `library add`/`update` refuse a bad one
- `lib/workspace/library_installer.rb` — Copies a library agent or skill into a checkout's install directory (`.claude/agents/` and `.claude/skills/` unless configured), never over a tracked path, and lists it in the common dir's `info/exclude`; `#install_user` copies to the user-level directory (no git)
- `lib/workspace/library_install_dirs.rb` — The one reader of the `library.install.{skills,agents,user_skills,user_agents}_dir` keys (project over global over default), read when a command runs; `LibraryInstaller` and `Commands::Library` get their directories only from it
- `lib/workspace/instruction_composer.rb` — Builds an agent's instructions from library packs under a heading per pack, and a workflow step's four layers (default packs, workflow, step, attempt); adds the pane's binding after `binding` and the project's `commands.test`/`commands.lint` after `commits`; `#start_packs`/`#compose_start` list and compose what `start` and `launch` send with the first prompt (the automatic `notes` pack, the `dev` pack when the project sets `dev.up`, then `--pack` names; `compose(skip:)` leaves a pack out of a workflow step)
- `lib/workspace/notes_config.rb` — Reads a project's `notes.instructions` (false turns the automatic `notes` pack off for `start` and `launch`)
- `lib/workspace/main_agent.rb` — Which coding agent a project's main agent pane runs (`claude`, `codex`, ..., or `none`), read from the panes of its tmuxinator config; `InstructionComposer` uses it to send the `handoff` pack to Claude Code and Codex only
- `lib/workspace/agent_commands.rb` — Reads `agent.kind` and `agent.commands.<kind>` through `ConfigResolver` (global, project, worktree): the effective agent kind, the command for a kind (default the provider's executable) `#executable_for` (the program that must be on PATH; the global layer alone for a nil workspace), `#names_for`, the program names that count as that agent, and `#aliases_for`/`#detector`; a bad stored value falls back to the default
- `lib/workspace/agent_executables.rb` — Read-only scan of `PATH` for each agent family's launchers (`<exe>` or `<exe>-suffix`, matched whole, never a bare prefix), with `shadowed` paths, configured commands not on PATH, and the `effective` program per kind; capped at 200 rows
- `lib/workspace/commands/agent_executables.rb` — `agent executables [--kind KIND] [--name WS] [--json]`: resolves the workspace, checks the kind (`unknown_agent_kind`), prints text or the `--json` document
- `lib/workspace/agent_command_check.rb` — What `config set agent.commands.<kind>` checks: an absolute path must exist and be an executable file (`agent_command_not_executable`); a bare name not on PATH or off-family is a warning
- `lib/workspace/agent_detector.rb` — `AgentDetector`, one workspace's way to find the coding agent in a pane: `AgentProvider.detect` plus the configured program names as aliases; `AgentCommands#detector` builds it for the session monitor, readiness checks, pane label searches and `restore`
- `lib/workspace/commands_config.rb` — Reads a project's `commands.test` and `commands.lint`
- `lib/library/play/` — The built-in instruction packs (`binding`, `orchestrator`, `commits`, `review`, `notes`, `handoff`, `dev`, `implementation-plan`, `research`, `report`, `plan-review`, `spine`, `promote`), read through `Library#builtin_store`; the `research` pack ends by adding a `note` inbox item (`inbox add --note`) and printing the note link from `ui open notes --path`; the `plan-review` pack reviews the plan, writes `plan-review.md` and posts an inbox item under `plan-review:WS:blocking` or `plan-review:WS:passed`
- `lib/workspace/commands/skills.rb` — `skills install [--install-all] [--dry-run] [--json]` (`confirmation_required` under `--no-input` when it would ask) and `skills uninstall [--dry-run] [--json]` (docs in `docs/README.skills.md`): links the six `lib/skills/<name>` directories into each chosen harness's skills directory (and `~/.agents/skills` when it exists, never created); one question through `Prompt.ask` for the harnesses found and not yet linked or declined (the ones left out are recorded as declined; end of input installs nothing and records nothing; `--install-all` asks nothing and clears declines); exit 1 when anything is refused or failed; codes `skill_path_exists`, `skill_link_foreign`, `skill_link_failed`, `skill_source_worktree`, `skills_source_missing`, `no_harness_found`. `#health` and `#repair` serve `doctor`: one `skills-<harness>` row per harness found and not declined (`ok`, `missing`, `dangling`, `conflict`), and `--fix` links the missing or dangling ones without replacing anything
- `lib/workspace/skill_harnesses.rb` — The four harnesses (Claude Code, Codex, Pi, OpenCode) with their skills directories (`CODEX_HOME` honoured); found by program on PATH or config directory; `~/.agents/skills` only when it exists
- `lib/workspace/skill_source.rb` — `SkillSource.stable_dir(dir)` is the Homebrew `opt` keg's libexec for a directory inside a Cellar keg whose opt link exists, else the directory (no worktree check; `relaunch`'s program). Where the links point: the Homebrew `opt` path, else the checkout's realpath; a linked worktree is refused (`skill_source_worktree`, read from `.git` and `commondir` alone, so no HOME, PATH or git call)
- `lib/workspace/skill_links.rb` — Inspects, plans and writes the six links of one skills directory: all six or none, a temp link renamed into place, an identical real directory moved to `skill-backups`, anything else refused with its `mv`; `#ours?` and `#removal_steps` serve `uninstall`
- `lib/workspace/skills_state.rb` — `skills.json` (`{"declined": []}`), flock-guarded through `FileLock` and `AtomicFile` (its own temp name and default file mode), so not `LockedJsonFile`; a corrupt file reads as empty
- `lib/skills/` — The six shipped skills (`workspace`, `workspace-agent-run`, `workspace-inbox`, `workspace-lifecycle`, `workspace-template`, `workspace-workflow`; each a directory with `SKILL.md`), what `skills install` links; `libexec.install "lib"` in the Homebrew formula ships them
- `script/check-skills` — Checks the skill files in `lib/skills` against the real CLI: each command, subcommand and `--flag` against `--help` (run in an empty temp HOME) and each error code against `error_codes.rb`; exit 1 on a mismatch
- `lib/workspace/commands/rename.rb` — `rename [WS] NEW [--name WS] [--dry-run] [--json]`: renames a stopped worktree workspace's branch, directory, name and session; `RenamePlan` first, then under `NameMigration#with_locks` and `DeferredSignals` the git steps (worktree move, branch rename; undone in reverse, `rename_failed`), then forward-only steps through `WorkspaceStoreRename`, notes, tasks, inbox, ledger and bindings, journal deleted, then `workspace_renamed` written (a failed delete keeps the journal and writes no event, so the re-run writes it once); a failure in any step keeps the journal (`rename_incomplete`) and the same command finishes it; launches nothing
- `lib/workspace/rename_plan.rb` — The read-only half of `rename`: the new names (as `start` makes them), the notes move (`move`, `with_checkout`, `stays`) and every refusal (`workspace_running`, `run_active` (read through an injected `run_store:`), `dev_lock_held`, `rename_*`); `resume: true` reads names and the notes decision from the journal and skips what the finished steps would trip; writes nothing
- `lib/workspace/rename_journal.rb` — One file per old workspace name, written before the first git step and deleted after the last; `#read` finds it by the old or the new name (`rename_in_progress` when unreadable)
- `lib/workspace/workspace_store_rename.rb` — Renames what is keyed on a workspace's name: tmux session, settings, run files, state dir, inbox files, state key, marker and last the tmuxinator config (held back while a step failed), whose render record moves and is rewritten (`TmuxinatorConfigWriter#carry_record`) before the config swap, so a retry that finds the config under the old name finishes it; a failed step is a warning and a retry finishes it; names checked against directory listings, a case-only change through a temporary name; shared by `NameMigration` and `rename`
- `lib/workspace/deferred_signals.rb` — `#hold { }` holds INT, TERM and HUP while steps run; `#caught` is asked between steps, `#report` names the signal in the error raised, `#note` takes one that arrived as an exception; an unreported one is sent again after the old handlers are back
- `lib/workspace/commands/` — Complex command objects (launch, kill, focus, start, agent, ensure_agent, lock, dev, notes, template, plan, pull_request, rebase, push, projects, capabilities, send, review, restore, snapshot, daemon, ui, binding, library, instructions, workflow, skills, rename)
- `lib/workspace/notes_setup.rb` — Fixes a new worktree's notes directory for `start` and `add`: writes the computed path as the worktree's own `notes.dir` (never over an existing value), makes the directory and its `info/exclude` line; every problem comes back as a warning, never an error
- `lib/workspace/start_ref.rb` — What `start` and `ticket show` make of a ref (JIRA key or URL, pull request, issue, branch): its `kind`, `key` and `branch` (`#call(input, root:, names:)` picks the lowercase key for a JIRA ref, else the existing branch that matches it without case, local names first), and `#project` for the project a worktree would join (the parent repo from inside a linked worktree)
- `lib/workspace/ticket_source.rb` — Reads a ticket's title (one line), body (64 KB cap) and URL, and a pull request's `cross_repository` (nil unless a boolean), with `gh` (pull request, issue) or `jira` (`jira issue view KEY --raw`) within 10s; a missing tool, a timeout or a failure is `ticket_source_unavailable`, an unknown ticket `ticket_not_found`; a branch runs nothing
- `lib/workspace/commands/go.rb` — `go [REF | "TEXT"] [--workflow ID | --file PATH] [--input KEY=VALUE]... [--here] [--text] [--base REF] [--dry-run] [--json]`: free text with `--here` and a run going on the checkout goes to `GoTask` (route `task`) before the workflow is chosen; reads the argument (any whitespace makes it a sentence: with `--here` or `--text` plain free text, else `RefInText` looks for one pull request, issue or ticket, links beating bare keys, a bare key needing its ticket to read through `TicketSource`, a repository the project does not track a mention only, and then it is that ref with the sentence as the prompt, `decision.extracted` naming the token; a lone word is a ref, a lone lowercase JIRA key only once its ticket reads, a workflow name only with `--workflow`), picks the workflow (`--workflow`, `workflows.by_ref.<kind>`, `workflows.default`, built in `pr-feedback` for a pull request else `rpiv`) and prints it with the reason, then calls `Workflow#run` in place or `WorkflowStart#call`; runs in place only in a linked worktree that is its own detected workspace off the default branch (a marker-less worktree, a bare repository's worktree, a detached HEAD or a rebase in progress never), and only for bare `go`, a ref for the current branch, or free text with `--here` (free text without it always goes to `WorkflowStart#call` as a new workspace, even from a worktree; `--here` where it can't run is `go_here_unavailable`, with a ref for another branch a `UsageError`), where it skips the fork check, as `workflow run` does, while every explicit ref goes through `WorkflowStart`; refuses `branch_not_allowed` (default or main checkout branch, symrefs and case aliases, free-text slugs, or the checkout `start` would reuse), `branch_exists` (free text that exists or differs in case, or the reused checkout holds another branch, `details.held`), `unknown_ref` (no such branch, a case variant or `origin/<branch>`, with `details.did_you_mean`) and `unknown_base`; `--base REF` goes to `WorkflowStart#call` on both start routes, is a `UsageError` where go runs in place or on the task path, and is checked (not a leading `-`, `Git#commit_exists?`) after the route is known and before the `go:` line prints; the `--json` row gains `decision` (with `extracted`) and `warnings`; docs in `docs/README.go.md`; its protected-branch rule is `ProtectedBranch`; go does not fill inputs from the branch; `file:` (`--file`) outranks `--workflow` and config (`--file` with `--workflow` is a usage error), is read through `WorkflowCatalog#load_file!` and reported as decision source `file`, reason `read from --file`.
- `lib/workspace/ref_in_text.rb` — `RefInText.scan(text)`: the GitHub pull request and issue URLs, Atlassian `/browse/` URLs and bare uppercase JIRA keys a sentence names, each a `Found` with a canonical `token` (URL or uppercase key) for `StartRef#call`, `id`, `repo` and `link`; `.word_key` reads a lone word as a key; `NOT_TICKETS` leaves out look-alikes such as `UTF-8`; pure text, no collaborators; `Commands::Go` is its caller
- `lib/workspace/commands/go_task.rb` — The task path of `go --here "TEXT"` when a run is already going on the checkout (`WorkflowRunStore#on_checkout`): refuses `--workflow`/`--input`/`--base` (`UsageError`), a run past every plan-reading step (`WorkflowDefinition.reads_plan?` from its current step, `checkout_has_run`), no plan (`no_plan`, never made) and a plan with `status: done` (`plan_done`), then `PlanTask#add` (`dry_run` honoured); answers the row with `workspace`, `run_id` and `decision.route: task`; types nothing
- `lib/workspace/protected_branch.rb` — `ProtectedBranch#call(branch, project)`: the reason and checkout when a branch is the default or the main checkout's (symrefs and case aliases followed), else nil; `#same?(branch, other, project)` compares two names the same way; `Commands::Go` and `WorkflowBranchInputs` use it

- `lib/workspace/event_log.rb` — Append-only event log for workspace state changes and agent activity. Events are stored as JSONL (one JSON object per line). The event log is the source of truth; the state file is a materialized view. State events (launches, kills, ...) are replayed into the state file. Activity events (dispatches, stage completions and failures, lock waits, per-pane agent state changes) are written with {#record} and ignored by {#reconstruct}; they are there to be read back with `workspace event-log show`, and the latest {AGENT_STATE} per pane lets a restarted agent daemon pick up each pane's state where the last one left off. Appends hold a shared `flock` on a sidecar lock file and {#compact} holds it exclusively, so no append lands in the old file while compact is rewriting it. An append that leaves the log over {DEFAULT_ROTATE_THRESHOLD} rotates it: under the same exclusive lock the log is renamed to `<log>.1` (older rotated files shift to `.2`, `.3`, and the one past {KEEP_ROTATED} is deleted) and a new file, seeded with the compacted state, is renamed into place. - `lib/workspace/event_stream.rb` — Reads the lifecycle event log and every agent daemon's hook event file as one stream, and keeps the cursor that resumes it. Each file is a source. A source remembers the file it is reading (by inode), the offset just past the last line read, and that line's time; a hook source also its `boot_id` and `seq`. The cursor is all of them, encoded so readers treat it as opaque. Lines are only read, so a slow reader never makes a writer wait. A file that was rotated or replaced (`event-log compact`) while a source was reading it is read to its end, through the handle already open, and the source goes on in the new file with only the lines after the last one's time: that skips the compacted seed a lifecycle rotation writes. Built with `workspace:` it reads only that daemon's hook file, and with `lifecycle_path: nil` no lifecycle log, which is how `DaemonWatch` scopes it.
- `lib/workspace/events_config.rb` — Reads the global `events:` block, as written by `workspace config set`. A bad stored value never stops the daemon: it falls back to the default with a warning, since `config set` already rejects bad input.
- `lib/workspace/commands/events.rb` — `workspace events`: the lifecycle event log and every agent daemon's hook event file, read as one stream (see {Workspace::EventStream}). It only reads files, so a slow reader never makes a daemon wait.
- `lib/workspace/hook_runner.rb` — Executes hook scripts defined in project configuration. Hooks are run as shell commands with workspace-specific environment variables. Automatically resolves the project root directory for the working directory.
- `lib/workspace/delivery_facts.rb` — Where a branch's commits have got to, from local git only (no fetch, no `gh`): pushed to its upstream, and on the default branch by {Workspace::Git#branch_vs_base}'s one rule. It reads and writes nothing.
- `lib/workspace/liveness.rb` — Answers "is this workspace's tmux session still there?" for tracked projects, so `list` and `status` can tell a running workspace from a stale state-file entry. A project is alive when its tmux session exists. The iTerm window is not consulted here; {Workspace::WindowLiveness} answers that.
- `lib/workspace/commands/init.rb` — Sets up workspace: creates the config directories, the global config and the agent hooks. It no longer copies tmuxinator templates (they ship as the built-in `default` set); it offers `workspace template import` for an edited copy an earlier version installed.
- `lib/workspace/commands/tile.rb` — Tiles all active windows for a project (base + worktrees) across the screen. Windows are arranged as equal-width columns filling the full screen.
- `lib/workspace/window_positions.rb` — Where each workspace's window last sat, one `window.json` per workspace in its state directory, so a later launch can put the window back.
