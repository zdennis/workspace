# Templates

Tmuxinator template sets, rendering, status, apply, adopt and the backup batches behind them. Full per-file detail, moved verbatim from `.claude/CLAUDE.md`; the one-line index there links here.

- `lib/workspace/cli/template.rb` — `CLI::Template`, the `template` family (`template_command:`, `backups_command:`, `relauncher:` (required), `common:`, `names:`, `working_dir:`): `#call(verb, args, invocation)` parses `list`, `show`, `path`, `variables`, `status`, `apply`, `render`, `validate`, `diff`, `new`, `edit` and `use` (`SUBCOMMANDS` names each verb's flags: `--scope`, `--kind`, `--name`, `--file`, `--sample`, `--diff`, `--against`, `--from`, `--all`, `--project [NAME]`, `--dry-run`, `--force`, `--rollback-all-on-error`, `--relaunch`, `--json`; `status` and `apply` take any number of workspace names, and `apply` hands the command's outcome to `Common#run_action`; `apply --relaunch` and `restore --relaunch` relaunch, inside that `run_action` block and after the command (and so its startup locks) is done, each workspace of an `applied` row that is `running` and not `record_only` (`would_apply` under `--dry-run`, which stops nothing and marks `would_relaunch`) or of a `restored` workspace row with `config_rewritten` whose session `Relauncher#running?` says is up, through `Relauncher#call(only_stopped: true)`; each such row gains `relaunch` (`relaunched`, `failed` with `relaunch_code` from the closed `RELAUNCH_CODES`, `would_relaunch`, `skipped` with `relaunch_own_workspace` for the caller's own workspace (`Names#workspace_here`, and also any for which `Relauncher#pane_in_session?` says `$TMUX_PANE` is in its session, or, where `$TMUX_PANE` is unset or unplaced for it, whose session `Relauncher#session_of?` matches `Relauncher#client_session` (read once); each helper answers nil on `Workspace::Error`/`SystemCallError` and `#running?` true; a `relaunch_own_workspace_unknown` warning when tmux placed the pane for none asked), never relaunched, `not_active` when `Relauncher#active_name` finds no state key, `not_running`); `extra` `relaunched`/`would_relaunch` is always present with the flag; warnings `relaunch_failed`, `relaunch_own_workspace`, `relaunch_not_active` and `relaunch_stop_warning`; an `ok` status becomes `partial` on a failure; after a roll back nothing is relaunched (rows `skipped`/`relaunch_skipped`, one `relaunch_skipped` warning, `Warning:` on stderr in text mode); text mode prints a line per relaunched or failed workspace; `render` and `validate` exit 1 when the command answers false; `new`, `edit` and `use` take the command's row through `Common#run_action` as an action document, `edit` exiting 1 on a `failed` row and handing the command an opener over `Common#open_in_editor` unless `--json`, which says on stderr that nothing was opened when no editor ran; `new` and `use` need a NAME), takes the workspace from `--name` or `Names#workspace_here` and hands the values to `Commands::Template`, writing and exiting only through the invocation; spec `spec/unit/workspace/cli/template_spec.rb` over a double command; the examples that go through `CLI#run` (its rescue funnel, the help pages, a real `Commands::Template` over a real `Library`) are in `spec/integration/workspace/cli/template_spec.rb`, built by `CLITestHelpers::TemplateFamilyCli`
- `lib/workspace/template_selection.rb` — `TemplateSelection#call(names:, all:, project:, working_dir:)`: the workspaces a multi-workspace `template` verb acts on (`status` and `apply` now; `backup` later): names given (each must have a config, else `unknown_workspace`), `--all` or `--project [NAME]` over `StatusScope` and `ProjectCatalog` (configured members only), else the current workspace; names mixed with a flag, or both flags, is a `UsageError`; a not-in-workspace error names NAMEs, `--project` and `--all` (not `--name`); spec `spec/unit/workspace/template_selection_spec.rb`
- `lib/workspace/template_status.rb` — `TemplateStatus#call(names)` / `#row(name)`: per workspace `current` (the file is byte for byte what a render writes today: the selected set's text filled with the record's inputs, the agent command recomputed from current agent settings as `render --name` does, and the record names the selected set), `stale` (the file is what was last rendered but a render today differs or the selected set is not the recorded one), `modified` (the file's sha is not `rendered_sha` and it is not today's render; `stale` and `reasons` still reported) or `untracked` (no usable record or no config); `reasons`: `template_switched` (even with identical text), `template_changed`, `agent_changed`, `template_unavailable`, `render_failed`; `#reproduces?(name, text)` says whether a render today writes exactly that text (`Commands::UpdatePaneCommand` asks it, through `template_status:`, before `set-command` lets the record follow the file; `TmuxinatorConfigWriter#patch` also keeps the record when the file was already edited); `.record_inputs(record, project_config)` is shared with `Commands::Template`; `Row` is a frozen value; `#assess(name)` is the row with what it was worked out from (`Assessment`: the record, the file, today's render, its inputs, the set's sha and the error that stopped a render), which `TemplateApply` writes from; reused by `doctor` later; specs `spec/unit/workspace/template_status_spec.rb` (doubles) and `spec/integration/workspace/template_status_spec.rb` (real writer and `ProjectConfig`, `set-command` and agent patches)
- `lib/workspace/template_apply.rb` — `TemplateApply` (`status:`, `writer:`, `backups:`, `locks:`, `project_config:`, `tmux:`, `differ:`, `retention:`), `template apply`: `#call(names, dry_run:, diff:, force:, rollback:)` opens one `TmuxinatorBackupStore` batch (none under `dry_run`), then per name inside `NameMigration#with_locks(name)` (which waits; a dry run, which writes nothing, takes no lock) reads everything its row decides: a config gone by then is `skipped: gone` and nothing is written; else `TemplateStatus#assess` (its `running` asks `Tmux#session_exists?` under `Tmux.stored_session_name`): `untracked` is skipped even with `force`, `modified` is skipped (`code` `template_modified`) unless `force`, a render that can't be made is `failed` with its error code, `current` is `unchanged`, else `#add` to the batch, `TmuxinatorConfigWriter#write` (inputs with today's agent pane text; `#write_record_for` alone, `record_only`, when the file already holds the render, as for a set switch to the same text), `#finish` with the after shas, `applied` (`would_apply` under `dry_run`) with `running` from `Tmux#session_exists?` (false for a record-only row); `LockUnavailable` is a `failed` row `workspace_locked`; `diff` adds each row's `diff` through `differ:`; with `rollback`, the first failed row puts back every batch entry under its own lock (the copy, keeping the file's current mode, or a delete for a file the batch created; a file changed since the batch wrote it is left), marks written rows `rolled_back` and the rest `skipped: not_reached`; then `discard_if_empty` and `prune` with `TmuxinatorBackupConfig`'s limits; answers a `Result` (`rows`, `backup`, `rolled_back`, `warnings`: `{code, message}` with `rollback_left_file`, `rollback_failed`, `rollback_unreadable`, `prune_failed`); spec `spec/integration/workspace/template_apply_spec.rb` (real `TemplateStatus`, writer, backup store and `NameMigration` locks over a temp dir; render, library and tmux doubles) A record with `approx` that reads `modified` is skipped as `skipped: approx` (code `template_approx`) unless `--force`.
- `lib/workspace/template_adopt.rb` — `TemplateAdopt` (`library:`, `project_config:`, `writer:`, `main_agent:`, `locks:`), `template adopt`: `#call(names, dry_run:)` builds the render record of a config that has none (a row each; under `NameMigration#with_locks`, a dry run takes none; everything read inside it): reads `name:`/`root:` (YAML), the `# path` header, the banner, a worktree's `Worktree — BRANCH (PROJECT)` echo line (else the project from the name and the branch from the checkout's `.git` HEAD or directory name) and `pre_window` task id, only a `# /absolute/path` header as the config path, and the agent through `MainAgent`, renders the template a new config would use now (`TemplateStatus.record_inputs`), and writes only the record: `exact` (the render is the file; `rendered_sha` is the file's) or `approx` (`approx: true` in the record, `rendered_sha` is the render's, so the file reads `modified` and `TemplateApply#one` skips it as `skipped: approx`, code `template_approx`, unless `--force`); outcomes `adopted` (`would_adopt`), `skipped` (`tracked`, `gone`), `failed` (`adopt_unrecoverable`, `workspace_locked`, a render error's code); `#recover(name)` is the inputs alone, for `template variables --name` (`(recovered)`); specs `spec/unit/workspace/template_adopt_spec.rb` (doubles) and `spec/integration/workspace/template_adopt_spec.rb` (a real `ProjectConfig` over the shipped templates)
- `lib/workspace/template_batch_files.rb` — `TemplateBatchFiles` (`backups:`, `writer:`), the file steps `TemplateApply`'s roll back and `Commands::TemplateBackups#restore` share: `#sha`, `#read`, `#facts(entry, kind)` (path, sha before, sha after or `:unknown`), `#before_bytes` (the batch's copy), `#write(entry, kind, bytes)` (through `TmuxinatorConfigWriter#put_config`/`#put_record`: an existing file keeps its mode by explicit chmod, a new config gets the umask's, a new record 0600; nil deletes) and `#put`; whether a changed file may be touched is each caller's rule; spec `spec/integration/workspace/commands/template_backups_spec.rb` and `spec/integration/workspace/template_apply_spec.rb`
- `lib/workspace/commands/template_backups.rb` — `Commands::TemplateBackups` (`library:` (optional; the stores a restored template set goes back to), `backups:`, `selection:`, `locks:`, `project_config:`, `retention:`, `writer:`, `output:`), `template backup [WS...|--all|--project]` (a `manual` batch, each workspace copied under its startup lock), `backups list`, `backups prune` (the retention keys; a workspace's newest batch stays) and `restore ID [WS...] [--force]` (a `restored` workspace row's `config_rewritten` says whether the config's bytes changed, for `--relaunch`): takes a batch of its own first (reason `restore`), each workspace under `NameMigration#with_locks` with its row read inside the lock (`unchanged`, `skipped: gone` when config and record are gone, the batch did not delete them and the checkout its record names is gone too (an accidental delete is restored), `failed: restore_conflict` when a file's sha is neither `sha_before` nor `sha_after` unless `--force`; a `manual` batch has only `sha_before`; config and record are read first and written together or the config is put back; an entry with no `sha_before` is deleted); `CLI::Template` takes it as `backups_command:`; spec `spec/integration/workspace/commands/template_backups_spec.rb` A batch `template import` took holds `sets` (the sets it replaced, and the ones it added, with no `sha_before`, which restore removes unless a key selects one and not `--force` (`template_in_use`, via `template_in_use:`)) (see `TmuxinatorBackupStore#add_set`): `restore` puts each back through `LibraryStore#copy_tree` after copying what it replaces into the restore batch, refusing one changed since (`restore_conflict`) unless `--force`; rows for a set carry `template` and `scope`; `backups list` shows `templates`.
- `lib/workspace/tmuxinator_backup_config.rb` — `TmuxinatorBackupConfig#keep`/`#max_age`: the global `tmuxinator.backups.keep` (default 20) and `.max_age` (seconds, nil unset) through `ConfigResolver`, a bad stored value falling back to the default with a warning; spec `spec/unit/workspace/tmuxinator_backup_config_spec.rb`
- `lib/workspace/text_diff.rb` — `TextDiff#call(old, new, old_label:, new_label:)`: a unified diff by `diff -u` over two temp files (empty when the same; the one process it starts), the `differ:` of `Commands::Template`; examples that run it are in `spec/system/workspace/commands/template_diff_spec.rb`
- `lib/workspace/commands/template.rb` — `template list|show|path|variables|status|render|validate|diff` (read-only) and `new|edit|use|export|import` (`export DIR` copies each user set and `templates.json` (shas, workspace version); `import [PATH]` validates every set first, backs up a replaced set into a batch of reason `import` (`backups:`), refuses one a key selects through `template_in_use:` unless `--force`; `library:`, `project_config:`, `writer:`, `template_validator:`, `differ:`, `config_command:`, `selection:`, `status:`, `apply:`, `adopt:`, `backups:`, `template_in_use:`, `tmuxinator_dir:`, `output:`, `error_output:`; `import` with no PATH reads the copies `init` once installed in `tmuxinator_dir`: when either is edited (`LegacyTmuxinatorTemplates.edited?`) both kinds become the global set `local` (a stock or missing kind from the built-in `default`), validated, and `tmuxinator.template` is set to it through `#use`, the old files left; with none edited it says so and writes nothing; global scope only): `#status(names:, all:, project:, cwd:, json:)` prints each selected workspace's `TemplateStatus` row (a table, or the `--json` document with `counts`); `#apply(names:, all:, project:, cwd:, dry_run:, diff:, force:, rollback:, json:)` runs `TemplateApply` over the selection and answers the action outcome (`status` `failed` after a roll back, `partial`/`failed` by failed rows, `dry_run`, else `ok`; `extra` `backup`, `rolled_back` and `skipped`, the skipped rows by reason), printing a line per row (`would apply` for a dry run's) (and its diff) unless `--json`; its `record_inputs` is `TemplateStatus.record_inputs`; `#list(workspace:, scope:, cwd:, json:)` is every `template` library entry (`Library#entries`) with `selected_for`, the kinds whose `Library#tmuxinator_template` picks it for that workspace (an edited installed copy shows as `legacy`; a selection that can't be found is a warning, not an error), `#show` and `#path` take a set (`Library#tmuxinator_set`) or, without one, each kind's selection, for `--kind` or both files (`library_source_missing` for a missing file); `#variables(kind:, workspace:, json:)` is the `TemplateVariables` table, with each row's value, as `render` would fill it (the record's inputs and `record_inputs`' current agent command), under `--name` (`(no record)` without one); `#render(set:, file:, kind:, workspace:, context:, sample:, diff:, json:)` validates the file through `TemplateValidator#call_file`, fills it with `ProjectConfig#render` from the record's inputs minus `agent_command` (current agent settings apply) or `TemplateVariables.sample_inputs`, writes nothing, reports problems on stderr or in `warnings`, still shows the text when a problem is an error and returns false then (`no_render_record` for a workspace with no record), `--diff` through the injected `differ:`; `#validate(set:, file:, kind:, workspace:, json:)` runs `TemplateValidator#call_file` over a set's files (the set named, else each kind's selection; `--file` is one file, its kind from `--kind`, else a `worktree.yml` name, else project), answers false on an error (warnings alone are true), and prints per file (`{ok, files[{kind, template, path, problems}], errors, warnings}`); `#diff(set:, against:, kind:, workspace:, json:)` is `differ:` over each file of the set and the same file of `against` (default `default`), labelled by path (`{files[{kind, template, path, against_path, changed, diff}], against, changed}`, always ok; `No differences from X.` on stderr); `--json` documents are `{schema_version, ok, ...}` (`selected`, `templates`, `warnings`; `variables`; render's `template`, `source`, `path`, `kind`, `workspace`, `inputs`, `content`, `diff`, `warnings`); `#new(name:, from:, scope:, workspace:, cwd:)` copies a set (`from` default `default`) into the global or project library through `LibraryStore#copy_tree` after `TemplateValidator#call_set` passes the source (`template_exists`, `invalid_template`, `unknown_template`; the name `legacy` is reserved; a lower-scope set of the same name it hides is a `shadows_template` warning, on stderr and in `warnings`), `#edit(set:, kind:, workspace:, opener:)` refuses a built-in set (`template_builtin_readonly`), calls `opener` with the file paths (the CLI's editor; nil under `--json`), then checks each file with `call_file` and answers a `failed` row (`invalid_template`) when one has an error, `#use(name:, scope:, kind:, workspace:, cwd:)` checks the name through `Library#tmuxinator_set` and calls `Commands::Config#set` for `tmuxinator.template` (`tmuxinator.worktree_template` for `--kind worktree`; global with no workspace and no scope), then says new configs render from it and existing ones are unchanged; each answers one action row for `CLI::Template`; spec `spec/unit/workspace/commands/template_spec.rb`; later template verbs (render, validate, apply, ...) land in this class
- `lib/workspace/core/template_variables.rb` — `TemplateVariables::ROWS`, the one frozen table of tmuxinator template placeholders (`name`, `kinds`, `required` per kind, `description`, `source`, `sample`, `input`: the render input key); `ProjectConfig#render` fills each row from its input and raises when a required one is nil while the template holds its placeholder; `.find`, `.for_kind`, `.sample_inputs(kind)` (each row's sample, agent kind `claude`, a task id for a worktree); `PRE_WINDOW` is a whole line, dropped without a task id; `AGENT_COMMAND` (required for a worktree) is the agent pane text, filled by `ProjectConfig#agent_pane_value` when no `agent_command` input is given
- `lib/workspace/template_variables_docs.rb` — Renders `TemplateVariables` into the generated `placeholders` block of `docs/README.template.md` (a table of placeholder, kinds, required, description, source, sample; pipes escaped); `script/generate-template-docs [--check]` runs it, and `spec/unit/workspace/template_variables_docs_spec.rb` fails on drift
- `lib/workspace/tmuxinator_config_writer.rb` — `TmuxinatorConfigWriter`, the writer of a tmuxinator config: `#write(name, text, kind:, template:, template_sha:, inputs:)` replaces the file through `AtomicFile` (an existing file keeps its mode, a new one gets the umask's) and then its render record `<Config#render_state_dir>/<name>.json` (`schema` 1, `kind`, `template`, `template_sha`, `inputs` with String keys, `rendered_sha`); `#write_record_for(name, text, ...)` writes only that record (`template apply` when another set renders the same text); `#record(name)` reads it back as a `Record` with a Symbol `kind` and Symbol-keyed `inputs`, ready for `ProjectConfig#render` (nil when missing, corrupt, another schema, or its `inputs.workspace_name` is not the name asked for); `#carry_record(name, from:, before:, after:) { |inputs| }` rewrites a record a rename moved (`rendered_sha` follows only a config that was current); `#remove_record(name)` deletes it (`ProjectConfig#remove`); `#patch(name, inputs:) { |text| }` rewrites the config, refreshing `rendered_sha` and merging `inputs` (no record: the file alone); `#current?` compares the file's sha256 with `rendered_sha`; built in `build_cli` and given to `ProjectConfig` (`#write`), `Commands::Launch` (`refresh_agent_pane`), `Doctor` (`--fix`) and `Commands::UpdatePaneCommand` (`set-command`), which patch through it with `agent_kind`/`agent_command` inputs, and to `NameMigration` and `Commands::Rename`, which hand it to `WorkspaceStoreRename` `Record#approx` (sidecar key `approx`, only when true) marks a record `template adopt` made without an exact render; `#write_record_for(..., approx:)` writes it.
- `lib/workspace/tmuxinator_backup_store.rb` — `TmuxinatorBackupStore` (`config:`, `writer:`, `clock:`, `id_suffix:`), the batches of tmuxinator config copies under `Config#tmuxinator_backups_dir` (`<state>/backups/tmuxinator/<id>/`, ids `YYYYMMDDTHHMMSS<microseconds>Z-xxxxxx`, made with a non-recursive mkdir and retried on a clash), each with a `manifest.json` written through `AtomicFile` (`id`, `created_at`, `reason`, `templates` shas, `entries`): `#open(reason:, templates:)` makes the batch and an empty manifest; `#add(batch, name:, path:)` copies one workspace's config and render record (`writer.record_path`) into it and lists the entry (`name`, `path`, `sha_before`, `record_path`, `record_sha_before`) before the config is written, a config or record that is a symlink is refused (`backup_symlink`), a name must be a plain file name, a failed copy raises, and a nil `sha_before` meaning the batch creates the file, so rollback and `restore` delete it; `#finish(batch, name:, sha_after:, record_sha_after:)` fills the after shas; `#create(entries, reason:, templates:)` is `open` plus an `add` per entry (`template backup`); `#discard_if_empty`; `#list` (newest first), `#find(id)` (`backup_not_found`, also for an id not shaped like one), `#copy_path`; `#prune(keep:, max_age:)` never removes a workspace's newest batch or, by age, one with an unreadable `created_at`, sweeps id-shaped directories with no manifest over an hour old, and answers the ids removed; the keys `tmuxinator.backups.keep` (default 20) and `.max_age` are global-scope and read by the caller (`TmuxinatorBackupConfig`), not by the store; spec `spec/unit/workspace/tmuxinator_backup_store_spec.rb`; built in `build_cli` for `TemplateApply` `#add_set`, `#finish_set` and `#set_copy_path` keep the template sets an import replaced under the manifest's `sets` (`name`, `scope`, `project`, `sha_before`, `sha_after` as `LibraryStore.tree_sha`) and `templates/SCOPE/PROJECT/NAME/`; reason `import`.
- `lib/workspace/template_validator.rb` — `TemplateValidator#call_set(dir)` (and `#call_file(kind, path)` for one file, saved or not): checks a tmuxinator template set without writing (it only reads the files): unknown placeholders (`TemplateVariables`, per kind), the ones a kind must hold (the table's `required`), `{{PRE_WINDOW}}` alone on its line, the agent pane (`- {{AGENT_COMMAND}}` as the whole unquoted item, else a literal line `ProjectConfig#template_claude_line` finds, which is the warning `literal_agent_pane`, read through `ProjectConfig#agent_pane_in_template?`; a worktree without either is an error, a project a warning), and a dummy render through `ProjectConfig#render` (a sample agent command that needs quoting) that must parse as YAML with `name`, `root`, `windows` and no `{{` left; answers a `Result` of `errors` and `warnings` (`Problem`s with `code`, `kind`, `message`); `Commands::Library` runs it on `add`/`update` of a `template` (`invalid_template`), `ConfigReport` on `tmuxinator.template` and `tmuxinator.worktree_template` (warnings `unknown_tmuxinator_template`, `invalid_tmuxinator_template`); `template validate` (T15) reuses it; spec `spec/integration/workspace/template_validator_spec.rb` over a real `ProjectConfig`
- `lib/workspace/template_in_use.rb` — `TemplateInUse#users(name, store)` (the global file as `workspace` nil, then each workspace, kind and `layer` whose `tmuxinator.template` or `tmuxinator.worktree_template` selects the set by a key, the default never counting; a project-scope set looks only at its project's workspaces; an unreadable config file is left out) and `#check!(name, store, verb:)` (`template_in_use`, `details.users`/`count`, retry `--force`); `Commands::Template#import` asks it before replacing a set and `Commands::Library#remove` before deleting a `template`, each passed `--force`; built in `build_cli`; spec `spec/unit/workspace/template_in_use_spec.rb`
- `lib/workspace/legacy_tmuxinator_templates.rb` — `SHIPPED_SHAS` (frozen, per kind): the sha256 of every version of the shipped tmuxinator templates, from `git log --follow` over `lib/library/template/default/<kind>.yml` (the command is in its header); `.edited?(kind, path)` (exists and not a shipped version) and `.path(kind, tmuxinator_dir)` (the copy an earlier `init` installed)
- `lib/workspace/tmuxinator_template_config.rb` — Reads `tmuxinator.template` (default `default`) and `tmuxinator.worktree_template` (unset follows it), layered global, project, worktree, through `ConfigResolver`: `#name(kind, workspace:)` answers the `template` library set name and the layer it came from; `Library#tmuxinator_template` calls it (`template_config:`)
- `lib/library/template/default/` — The built-in `default` tmuxinator template set: `project.yml` (standard projects), `worktree.yml` (git worktree projects) and a `README.md`; `init` no longer copies them (it prints one line offering `template import` only for an edited copy an earlier version installed, `Commands::Init#offer_legacy_import`; `-f`/`--force` is accepted and ignored); a `template` library kind (`library list --kind template`)

- `lib/workspace/tmuxinator_report.rb` — Builds the document behind `workspace tmux show --json`: a workspace's tmuxinator file as session fields, windows and panes, with what each pane's command looks like and what tmux is running now. Read-only. A file that can't be parsed is reported as data (message, line, column), not raised.
- `lib/workspace/commands/update_pane_command.rb` — Updates a pane's shell command in a project's tmuxinator config file. Supports replacing an existing pane or appending a new one.
