# Work queue

The per-workspace work queue: sequential items kept in the workspace's state directory (`Config#work_queue_path`, `#work_queue_history_path`), and the log of finished ones. The one-line index in `.claude/CLAUDE.md` links here.

- `lib/workspace/work_queue_history.rb` — `WorkQueueHistory.new(path:, clock: Time, retention: RETENTION)` over `work-queue-history.jsonl` (`Config#work_queue_history_path(name)`): one JSON line per finished item, oldest first, mode 0600, written whole through `AtomicFile`. `RETENTION` is 365 days in seconds. Every read and write holds the exclusive lock of a sidecar `<path>.lock` (`FileLock`) and prunes first, so a prune rewrite can't lose an append and pruning needs no daemon. A line's age is its `finished_at` (ISO 8601 UTC, milliseconds; `append` stamps it from the clock when the entry has none); a line whose time can't be parsed is kept, as `EventLog` keeps one, and a line that is not a JSON object stays in the file and is skipped by reads. `#append(entry)` and `#append_locked(entry)` do the same; the second is named for the queue store, which calls it while it holds its own lock (lock order: the store's, then this one). `#entries(since:, before:, state:, prune: true)` (`prune: false` reads without rewriting: lines past the retention are left out of the answer and stay in the file) filters on `finished_at` (an unreadable time fails a time filter) and `outcome`; no file reads as `[]` without making one. `#find(prefix)` returns the one entry whose `id` starts with it (an exact id wins over longer ids it prefixes) and raises `unknown_queue_item` or `ambiguous_queue_item` (`details.matches`). `#clear(before:)` or `#clear(all: true)` (exactly one, else `ArgumentError`) returns how many entries it removed. `#prune` drops lines past the retention and returns the count.
- `lib/workspace/work_queue_store.rb` — `WorkQueueStore.new(path:, history:, clock: Time, id_generator: -> { SecureRandom.hex(4) }, max_items: MAX_ITEMS, workspace: nil, event_log: nil)` over `work-queue.json` (`Config#work_queue_path(name)`), modelled on `PromptQueueStore` over `LockedJsonFile` (sidecar flock, whole-file atomic write, mode 0600, `JSON.generate` fingerprint). The file is `{revision, enabled, paused, items}`: `revision` is an integer bumped on every write, `enabled` is absent until `set_enabled` (nil means use config), `paused` is `{reason, at}` or nil. An item carries `id`, `kind`, `spec`, `headless`, `on_fail`, `added_at`, `added_by`, `dedupe_key`, `state` (`queued|starting|active|held`), `started_at`, `reason`, `result{run_id, log_path, error}`, and while `starting` the claim fields `claim` (random token), `claimed_at` and `claimed_by{pid, started}`. Items that are not `queued` come first; at most one exists (`Transaction#current`). A file that is not a queue document or not JSON raises a plain `Workspace::Error` and changes nothing (the prompt queue's rule, no code). `#transaction { |queue| }` is the one locked read-modify-write: it yields a `Transaction`, bumps `revision`, writes and prunes the history only when the block changed something, and writes nothing when the block raises. `Transaction` has `items`, `current`, `enabled`, `paused`, `find(id)`, `add(kind:, spec:, position:, headless:, on_fail:, dedupe_key:, added_by:)` (positions `:bottom`, `:top`, `:after_current`, `{before: ID}`, `{after: ID}`; `:top` and `:after_current` both land first among the queued items, since the current item always leads; a repeated `dedupe_key` returns `:unchanged` and the existing item; `queue_full` past `max_items`), `remove(ids)` (all or none), `move(id, before:|after:|top:|bottom:, if_revision:)` (`:unchanged` when nothing moves; `stale_revision` with `details.revision`), `set_enabled`, `pause(reason)` (keeps the first reason), `resume`, `claim_next(claimed_by:)` (first queued item becomes `starting` with its claim; nil while any starting, active or held item exists), `record_run(id, claim:, run_id:)` (`:recorded` and clears the claim, or `:lost` when the item is gone, not `starting` or carries another claim), `adopt(id, run_id:)` (a `starting` item whose run was found), `hold(id, reason:)` (only an `active` item) and `unhold(id)` (only a `held` one), both nil otherwise, and `finish(id, outcome:, reason:, error:, claim: nil)`, which removes the item and queues a history entry (the item minus its claim fields and `state`, plus `outcome` and `reason`) that `transaction` appends with `history.append_locked` after the queue file is written, still under the lock, so a raising block or a failed write leaves no history line; with `claim:` it returns `:lost` and changes nothing when the item is gone or carries another claim. `move` with `before:` or `after:` naming the item itself gives `:unchanged`; an empty prefix raises `unknown_queue_item`. Positions are from 1 across all items. Prefixes resolve as in `WorkQueueHistory#find` against pending items (`unknown_queue_item`, `ambiguous_queue_item`). `remove` and `move` of a `starting` item raise `item_starting`, of an active or held one `item_active`; a `before:` target that is not queued raises the same. `#add`, `#remove`, `#move`, `#set_enabled`, `#pause` and `#resume` are one-call transactions; `#snapshot` is a deep copy read under a shared lock (an empty queue when there is no file) and `#find(prefix)` reads one item. `WorkQueueStore.summary(item)` is what an item runs in one line (workflow, ref, prompt; go argument, text, workflow; whitespace collapsed), which `Commands::WorkQueue` truncates for its WHAT column. Each transition queues one `EventLog` line in the transaction and `transaction` records them through `event_log.record(project: workspace, data: {..., workspace})` after the queue file and history are written, still under the lock, so two passes racing (two store instances over one file) record each once and a raising block records none: `record_run` (`:recorded`) and `adopt` give `work_queue_item_started` (`id`, `kind`, `what`, `run_id`), `hold` of an active item `work_queue_item_held` (`id`, `reason`), `finish` that removes an item `work_queue_item_finished` (`id`, `outcome`, `reason`, `run_id`), `pause` of an unpaused queue `work_queue_paused` (`reason`, the current item's `id`) and `resume` of a paused one `work_queue_resumed`; `build_cli`'s store factory passes the workspace and its `EventLog`, the daemon desk's store (read only) none. Specs `spec/unit/workspace/work_queue_store_events_spec.rb`, and the racing passes in `work_queue_advance_spec.rb`.
- `lib/workspace/work_queue_starters.rb` — `WorkQueueStarters.new(workflow:, workflow_start:, go:, workflow_project:, catalog:)`; `#to_h` is `{"workflow" => method(:workflow), "go" => method(:go)}`, the Hash `WorkQueueAdvance` takes, so later parts add kinds as entries. Each starter is `(item, workspace:, checkout:, note:) -> run_id` and raises on refusal; `checkout` is a `WorkflowStart::Here` with `caller_pane: nil`, so a run is never parked into the pane that ran the pass. Everything is read from `checkout.path`, never the cwd. `workflow` with no `ref` in the spec calls `workflow_start.check_agent!` (project workspace from `locate_project(path)`), then `Workflow#run(id:, workspace:, worktree:, inputs:, note:, project:, fill_from_branch: true)`, with `task` taken from the spec's `prompt` when the definition (read through `catalog`) declares `task` and the inputs lack it. With a `ref` it calls `WorkflowStart#call(id:, ref:, prompt:, inputs:, note:, headless:, here:, root:)`. `go` calls `Go#call(argument:, text:, workflow:, inputs:, headless:, checkout:, note:)` and raises `run_going` when `decision.route` is `task`. The run id is `row["run"]["id"]`. Spec keys: workflow `workflow`, `ref`, `prompt`, `inputs`; go `argument`, `text`, `workflow`, `inputs`; `headless` is the item's own field.
- `lib/workspace/work_queue_advance.rb` — `WorkQueueAdvance.new(store_factory:, run_store:, starters:, lock_holder:, status:, clock: Time)`; `store_factory` maps a workspace name to its `WorkQueueStore`, `starters` is `WorkQueueStarters#to_h`, `status` is the `WorkflowStatus` a live park's actions come from. `#call(workspace:, checkout:)` runs one pass and returns rows `{"outcome", "id", "kind", "reason", "run_id", "next_actions"}` (`id` and `kind` nil on a refusal; next actions from `NextAction`, the queue's verbs carrying `--name WORKSPACE`). First transaction, whatever the toggle or pause: a `starting` item whose `claimed_by` holder is alive (`LockHolder#holder_alive?`; a `Workspace::Error` counts as alive) gives `unchanged`/`starting` with `work-queue status --name WS` (its `why` says the start is in progress; run advance again once it lands) and ends the pass; a dead holder's item is looked up by the `(claim TOKEN)` in `WorkflowRun#note` across `run_store.unarchived` and `finished_since(claimed_at)` (epoch when `claimed_at` can't be parsed), then `adopt`ed and read below, or finished `interrupted` with the queue paused `interrupted`. An `active` or `held` item's run (`run_store.run`) maps in order: `completed` finishes `succeeded`; `failed`/`cancelled` finish with that outcome and reason, pausing with it unless `on_fail` is `continue`; a live park (`WorkflowEngine.parked == :waiting`) is `held`/`parked` with the run's `current.reason.actions` from `status.run` (else `workflow status RUN`), read after the last transaction so the flock is never held across a status render; a waiting gate on the current step is `held`/`gate` with `workflow approve RUN`; a reason code in `FAILURE_REASONS` (`failed_check`, `budget_spent`, `run_timed_out`) is `held` with that reason, pausing with it when the item was not already held for it, next actions `workflow status RUN` and `work-queue skip ID`; anything else is `active` (a held item is unheld). A run id that is nil or `unknown_run` finishes the item `interrupted`/`unknown_run` and pauses. Then, with no current item left, it refuses (`unchanged`) by `disabled` (toggle not `true`; `work-queue enable`), `paused` (`work-queue resume`), `empty`, or `run_going` (a run of `run_store.going` in this workspace; its id in `run_id`), else claims the first queued item with `claimed_by {pid, started}` (`LockHolder#start_time`, nil when `ps` fails); the claimed item is copied out by a JSON round-trip. The starter runs outside the lock with note `Started by work-queue item ID (claim TOKEN)`. A second transaction records the run (`started`); a `:lost` record writes nothing over the item, pauses `claim_lost` and returns outcome `claim_lost` with the run id. A starter that raises `Workspace::Error` may have made its run first (`WorkflowStarter#start` writes it before dispatch): the claim token is looked up as for a dead holder, and a run found is recorded (`claim_lost` if the claim no longer matches) and read as above, so the item is not finished. With no run found it finishes the item `launch_failed` (reason: the error's code, `usage_error` for a code-less `UsageError`, `start_failed` for a code-less `Error`; message in `result.error`) and pauses `launch_failed`; a kind with no starter is `launch_failed`/`unknown_kind`. A pass that finishes the current item goes on to the refusals and start in the same transaction.
- `lib/workspace/work_queue_desk.rb` — `WorkQueueDesk.new(workspace:, store:, run_store:, executable:, log_path:, spawner: nil, waiter: nil, clock:, logger:)`, the agent daemon's part in its workspace's queue, built per workspace by `Workspace.build_agentd_parts` (`work_queue_desk_factory:`, given `workspace:`; nil builds one over `Config#work_queue_path`, the builder's `workflow_store:` and `Config#agent_log_path`) as `AgentdParts#work_queue_desk`. It never runs the pass in the daemon: it starts `ruby bin/workspace work-queue advance --name WORKSPACE` as its own process (`spawner:`, default `Process.detach(Process.spawn)` with `TMUX_PANE` unset, the nudger's way), so a start never runs on the daemon's threads and the pass is the one `WorkQueueAdvance` a person runs. `#turn_ended` (from `HookFanout` on a main agent's Stop: after the `workflow advance` the nudger started has exited, through `WorkflowNudger#turn_ended`'s `on_exit:`, or at once when no run was woken) always asks for a pass; `#scan` (the monitor's after-scan call, so every `agentd.poll_interval`) asks only when what a pass reads changed since the last pass ended: the queue's `revision` plus, with an item current, its run's hash (`:unknown` for an `unknown_run`), else the workspace's `run_store.going` ids; with an item current it also asks after `BACKSTOP` (60) seconds, since a park's time running out changes no file. A queue with no items asks for nothing; whether it is on, paused or blocked is the pass's question. One pass at a time under a Mutex: a turn end during a pass runs another right after it, a scan then asks for nothing. A spawner that gives no thread counts as a pass that ended; a spawn, thread read or queue read that raises is logged at debug and nothing raises. Spec `spec/unit/workspace/work_queue_desk_spec.rb`; fake `RecordingWorkQueueDesk` in `spec/support/fakes/agentd_parts.rb`.
- `lib/workspace/commands/work_queue.rb` — `Commands::WorkQueue.new(store_factory:, history_factory:, advance:, decisions:, run_store:, checkout:, go:, status_scope:, agent_ensurer:, agent_running:, clock: Time, watch_loop: nil, working_dir: Dir.pwd, output:, error_output:, input:)`, one method per verb over parsed values; it prints for a person and returns data for `run_action` or `JsonEnvelope.document`. The workspace is `name`, else the one `working_dir` is in, through `WorkspaceCheckout#resolve(allow_detached: true)`, except `advance` and `cancel --and-continue`, which need a branch. Actions return rows `{outcome, id, position, kind}` (plus `run_id`, `count`, `warning`, `next_actions` where they apply); `#action_extra(name:)` gives the document's `extra`, `{queue, revision}`. `#add(kind:, spec:, name:, position:, headless:, on_fail:, dedupe_key:, added_by:)` refuses a `go` item with `go_here_unavailable` when `Go#in_place_checkout(path, workspace:)` is nil, and otherwise calls the store's `add` (`added` or `unchanged`). `add` and `enable` then call `agent_ensurer` (`Commands::EnsureAgent`, from `build_cli`) for the workspace; a result that is not `ok?` (or an ensurer that raises `Workspace::Error`) prints `Warning:` to the error stream and adds `warnings` `[{code: daemon_not_started, workspace, message}]` to the row (`invalid_config` reads "its pipeline config can't be used"), and the change stands. `#rm(ids:)`, `#move(id:, before:, after:, top:, bottom:, if_revision:)`, `#enable`, `#disable` and `#resume` (the pause only) are the store's own calls. `#skip(id: nil)` takes the held item (the id given must be held), finishes it `skipped`, clears the pause and never touches its run; a run still going adds `warning` and a `workflow cancel RUN` next action; none held is `item_not_held` with a `work-queue resume` next action in `details.next_actions`. `#cancel(id: nil, and_continue: false)` takes the current item (a queued one or none is `item_not_active`), validates in one transaction, calls `decisions.cancel(run_id, actor: "person")` outside it, then finishes the item `cancelled` if it is still there and pauses unless `and_continue`, which then runs a pass. `skip` and `cancel` of a `starting` item raise `item_starting`. `#advance` gives the pass `WorkflowStart::Here` of the workspace's root. Reads return a Hash with `warnings`: `#list` and `#status` (`name:`, or `project:` as `StatusScope#resolve`, read only through `store.snapshot`) give `queues` with `state` (`on`, `off` or `paused`; an unset toggle is off), `daemon_running` (`agent_running.call(workspace)`, `Config#agent_running?` from `build_cli`; a raising `Workspace::Error` counts as down), and `next_actions` (`agentd --ensure --name WS` and, with items and no pause, `work-queue advance` only for an enabled queue whose daemon is down), and `warnings` `daemon_not_running` (`code`, `workspace`, `message`) for each enabled queue whose daemon is down, also printed to the error stream; the footer and status line end `daemon up` or `daemon down`; `#show(id:)` gives one pending item with `result.log_path` nil for workflow and go items; `#active` adds `waiting_on` read from the run; `#watch_list(name:, project:, interval:)` and `#watch_active(name:, interval:)` redraw the same output through the injected `watch_loop:` ({WatchLoop}, built in `build_cli`; nil builds one over `output` and `sleep`) until Ctrl-C and return `{exit_code: 0}`, each frame written to the loop's buffer by the same renderers, with `daemon_not_running` as `Warning:` lines in the frame, not on the error stream; `#history_list(since:, before:, state:, project:)` (with `project:` it reads through `WorkQueueHistory#entries(prune: false)`, which filters lines past the retention in memory and never rewrites the file; the history entry points add `next_actions`) and `#history_show(id:)` (its `next_actions` is the `work-queue add` command rebuilt from the entry's kind and spec) read the history; `#history_clear(before:, all:, yes:, json:)` takes exactly one of `before` and `all` (else `UsageError`) and, without `yes`, asks on a tty and raises `confirmation_required` (retry flag `--yes`, destructive) under `json`, `--no-input` or a non-tty. `#active` reports the item's real position; a held item with no run id gets no `workflow approve` or `workflow status` next action.
- `lib/workspace/cli/work_queue.rb` — `CLI::WorkQueue.new(work_queue_command:, common:)`, the family `CLI::ROUTES` sends both `work-queue` and `wq` to. `SUBCOMMANDS` maps each verb to the flags it takes and `HISTORY_SUBCOMMANDS` does the same for `history list|show|clear`; a flag the verb does not take is a usage error, as are `--name` with `--project`, an unknown `add` kind (only `workflow` and `go`), two of `--top`, `--after-current`, `--before` and `--after`, `move` without exactly one of `--before`, `--after`, `--top` and `--bottom`, `history clear` without exactly one of `--before` and `--all`, a non-numeric `--if-revision`, `--watch` with `--json`, `--interval` without `--watch` or of 0 or less (`--watch` and `--interval` are taken by `list` and `active`, which then call `watch_list` or `watch_active` and exit with the result's `exit_code`), a bad `--on-fail` or `--input`, and a `--since` or `--before` date that is not `YYYY-MM-DD` (optionally with a time), which it turns into a `Time`. `add workflow ID` builds the spec `{workflow, ref, prompt, inputs}` and `add go [ARG]` builds `{argument, text, workflow, inputs}`, leaving out what was not given. An action verb goes through `Common#run_action` as `work-queue VERB`; its `results` rows get the queue as `workspace`, and under `--json` the document carries `Commands::WorkQueue#action_extra` (`queue`, `revision`) beside them. `advance` and `cancel --and-continue` print one sentence per pass row, and their document status and exit code are `failed` or `partial` (1 or 3) when a row's outcome is `launch_failed`, `claim_lost`, `interrupted`, `failed` or `cancelled` (the `cancel` row itself does not count); a held item is not a failure. `add go` needs its ARG. A read verb prints for a person through the command; under `--json` it diverts that output to stderr and prints `JsonEnvelope.document` with the payload under `PRIMARY_KEYS` (`queues`, `item`, `entries`, `entry`) and the rest of the command's Hash beside it. Help pages are `HelpPages::WORK_QUEUE`, one per verb; `--help` on `work-queue` and `wq` print the same page.
