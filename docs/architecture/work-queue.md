# Work queue

The per-workspace work queue: sequential items kept in the workspace's state directory (`Config#work_queue_path`, `#work_queue_history_path`), and the log of finished ones. The one-line index in `.claude/CLAUDE.md` links here.

- `lib/workspace/work_queue_history.rb` — `WorkQueueHistory.new(path:, clock: Time, retention: RETENTION)` over `work-queue-history.jsonl` (`Config#work_queue_history_path(name)`): one JSON line per finished item, oldest first, mode 0600, written whole through `AtomicFile`. `RETENTION` is 365 days in seconds. Every read and write holds the exclusive lock of a sidecar `<path>.lock` (`FileLock`) and prunes first, so a prune rewrite can't lose an append and pruning needs no daemon. A line's age is its `finished_at` (ISO 8601 UTC, milliseconds; `append` stamps it from the clock when the entry has none); a line whose time can't be parsed is kept, as `EventLog` keeps one, and a line that is not a JSON object stays in the file and is skipped by reads. `#append(entry)` and `#append_locked(entry)` do the same; the second is named for the queue store, which calls it while it holds its own lock (lock order: the store's, then this one). `#entries(since:, before:, state:)` filters on `finished_at` (an unreadable time fails a time filter) and `outcome`; no file reads as `[]` without making one. `#find(prefix)` returns the one entry whose `id` starts with it (an exact id wins over longer ids it prefixes) and raises `unknown_queue_item` or `ambiguous_queue_item` (`details.matches`). `#clear(before:)` or `#clear(all: true)` (exactly one, else `ArgumentError`) returns how many entries it removed. `#prune` drops lines past the retention and returns the count.
- `lib/workspace/work_queue_store.rb` — `WorkQueueStore.new(path:, history:, clock: Time, id_generator: -> { SecureRandom.hex(4) }, max_items: MAX_ITEMS)` over `work-queue.json` (`Config#work_queue_path(name)`), modelled on `PromptQueueStore` over `LockedJsonFile` (sidecar flock, whole-file atomic write, mode 0600, `JSON.generate` fingerprint). The file is `{revision, enabled, paused, items}`: `revision` is an integer bumped on every write, `enabled` is absent until `set_enabled` (nil means use config), `paused` is `{reason, at}` or nil. An item carries `id`, `kind`, `spec`, `headless`, `on_fail`, `added_at`, `added_by`, `dedupe_key`, `state` (`queued|starting|active|held`), `started_at`, `reason`, `result{run_id, log_path, error}`, and while `starting` the claim fields `claim` (random token), `claimed_at` and `claimed_by{pid, started}`. Items that are not `queued` come first; at most one exists (`Transaction#current`). A file that is not a queue document or not JSON raises a plain `Workspace::Error` and changes nothing (the prompt queue's rule, no code). `#transaction { |queue| }` is the one locked read-modify-write: it yields a `Transaction`, bumps `revision`, writes and prunes the history only when the block changed something, and writes nothing when the block raises. `Transaction` has `items`, `current`, `enabled`, `paused`, `find(id)`, `add(kind:, spec:, position:, headless:, on_fail:, dedupe_key:, added_by:)` (positions `:bottom`, `:top`, `:after_current`, `{before: ID}`, `{after: ID}`; `:top` and `:after_current` both land first among the queued items, since the current item always leads; a repeated `dedupe_key` returns `:unchanged` and the existing item; `queue_full` past `max_items`), `remove(ids)` (all or none), `move(id, before:|after:|top:|bottom:, if_revision:)` (`:unchanged` when nothing moves; `stale_revision` with `details.revision`), `set_enabled`, `pause(reason)` (keeps the first reason), `resume`, `claim_next(claimed_by:)` (first queued item becomes `starting` with its claim; nil while any starting, active or held item exists), `record_run(id, claim:, run_id:)` (`:recorded` and clears the claim, or `:lost` when the item is gone, not `starting` or carries another claim), `adopt(id, run_id:)` (a `starting` item whose run was found), `hold(id, reason:)` (only an `active` item) and `unhold(id)` (only a `held` one), both nil otherwise, and `finish(id, outcome:, reason:, error:, claim: nil)`, which removes the item and queues a history entry (the item minus its claim fields and `state`, plus `outcome` and `reason`) that `transaction` appends with `history.append_locked` after the queue file is written, still under the lock, so a raising block or a failed write leaves no history line; with `claim:` it returns `:lost` and changes nothing when the item is gone or carries another claim. `move` with `before:` or `after:` naming the item itself gives `:unchanged`; an empty prefix raises `unknown_queue_item`. Positions are from 1 across all items. Prefixes resolve as in `WorkQueueHistory#find` against pending items (`unknown_queue_item`, `ambiguous_queue_item`). `remove` and `move` of a `starting` item raise `item_starting`, of an active or held one `item_active`; a `before:` target that is not queued raises the same. `#add`, `#remove`, `#move`, `#set_enabled`, `#pause` and `#resume` are one-call transactions; `#snapshot` is a deep copy read under a shared lock (an empty queue when there is no file) and `#find(prefix)` reads one item.
- `lib/workspace/work_queue_starters.rb` — `WorkQueueStarters.new(workflow:, workflow_start:, go:, workflow_project:, catalog:)`; `#to_h` is `{"workflow" => method(:workflow), "go" => method(:go)}`, the Hash `WorkQueueAdvance` takes, so later parts add kinds as entries. Each starter is `(item, workspace:, checkout:, note:) -> run_id` and raises on refusal; `checkout` is a `WorkflowStart::Here` with `caller_pane: nil`, so a run is never parked into the pane that ran the pass. Everything is read from `checkout.path`, never the cwd. `workflow` with no `ref` in the spec calls `workflow_start.check_agent!` (project workspace from `locate_project(path)`), then `Workflow#run(id:, workspace:, worktree:, inputs:, note:, project:, fill_from_branch: true)`, with `task` taken from the spec's `prompt` when the definition (read through `catalog`) declares `task` and the inputs lack it. With a `ref` it calls `WorkflowStart#call(id:, ref:, prompt:, inputs:, note:, headless:, here:, root:)`. `go` calls `Go#call(argument:, text:, workflow:, inputs:, headless:, checkout:, note:)` and raises `run_going` when `decision.route` is `task`. The run id is `row["run"]["id"]`. Spec keys: workflow `workflow`, `ref`, `prompt`, `inputs`; go `argument`, `text`, `workflow`, `inputs`; `headless` is the item's own field.
- `lib/workspace/work_queue_advance.rb` — `WorkQueueAdvance.new(store_factory:, run_store:, starters:, lock_holder:, status:, clock: Time)`; `store_factory` maps a workspace name to its `WorkQueueStore`, `starters` is `WorkQueueStarters#to_h`, `status` is the `WorkflowStatus` a live park's actions come from. `#call(workspace:, checkout:)` runs one pass and returns rows `{"outcome", "id", "kind", "reason", "run_id", "next_actions"}` (`id` and `kind` nil on a refusal; next actions from `NextAction`, the queue's verbs carrying `--name WORKSPACE`). First transaction, whatever the toggle or pause: a `starting` item whose `claimed_by` holder is alive (`LockHolder#holder_alive?`; a `Workspace::Error` counts as alive) gives `unchanged`/`starting` with `work-queue status --name WS` (its `why` says the start is in progress; run advance again once it lands) and ends the pass; a dead holder's item is looked up by the `(claim TOKEN)` in `WorkflowRun#note` across `run_store.unarchived` and `finished_since(claimed_at)` (epoch when `claimed_at` can't be parsed), then `adopt`ed and read below, or finished `interrupted` with the queue paused `interrupted`. An `active` or `held` item's run (`run_store.run`) maps in order: `completed` finishes `succeeded`; `failed`/`cancelled` finish with that outcome and reason, pausing with it unless `on_fail` is `continue`; a live park (`WorkflowEngine.parked == :waiting`) is `held`/`parked` with the run's `current.reason.actions` from `status.run` (else `workflow status RUN`), read after the last transaction so the flock is never held across a status render; a waiting gate on the current step is `held`/`gate` with `workflow approve RUN`; a reason code in `FAILURE_REASONS` (`failed_check`, `budget_spent`, `run_timed_out`) is `held` with that reason, pausing with it when the item was not already held for it, next actions `workflow status RUN` and `work-queue skip ID`; anything else is `active` (a held item is unheld). A run id that is nil or `unknown_run` finishes the item `interrupted`/`unknown_run` and pauses. Then, with no current item left, it refuses (`unchanged`) by `disabled` (toggle not `true`; `work-queue enable`), `paused` (`work-queue resume`), `empty`, or `run_going` (a run of `run_store.going` in this workspace; its id in `run_id`), else claims the first queued item with `claimed_by {pid, started}` (`LockHolder#start_time`, nil when `ps` fails); the claimed item is copied out by a JSON round-trip. The starter runs outside the lock with note `Started by work-queue item ID (claim TOKEN)`. A second transaction records the run (`started`); a `:lost` record writes nothing over the item, pauses `claim_lost` and returns outcome `claim_lost` with the run id. A starter that raises `Workspace::Error` may have made its run first (`WorkflowStarter#start` writes it before dispatch): the claim token is looked up as for a dead holder, and a run found is recorded (`claim_lost` if the claim no longer matches) and read as above, so the item is not finished. With no run found it finishes the item `launch_failed` (reason: the error's code, `usage_error` for a code-less `UsageError`, `start_failed` for a code-less `Error`; message in `result.error`) and pauses `launch_failed`; a kind with no starter is `launch_failed`/`unknown_kind`. A pass that finishes the current item goes on to the refusals and start in the same transaction.
