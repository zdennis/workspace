# Workflow

Workflow definitions, the run store, the engine and its phase classes, review rounds, sweeps, and status readers. Full per-file detail, moved verbatim from `.claude/CLAUDE.md`; the one-line index there links here.

- `lib/workspace/workflow_seed.rb` — `WorkflowSeed.task_text(ticket, prompt)`, the `task` text `workflow start` seeds (`KEY: title (url)`, then the prompt), and `.fillable?(definition, name, inputs)`, the guard that an input is declared and not set by `--input`; `WorkflowStart` and `WorkflowBranchInputs` seed through it
- `lib/workspace/workflow_branch_inputs.rb` — `#call(definition, worktree, inputs)`: what `workflow run` fills from the target checkout's branch (`FILLABLE`: `task`, `pr`; declared and unset only): an open pull request (`PullRequestStatus#summary`) gives `pr` and `task` `#N: Title (url)`, else `task` is `Branch NAME`; nothing on a protected branch, detached HEAD, mid-rebase or in a plain clone; gh trouble never fails the run; `Commands::Workflow#run` calls it (`fill_from_branch:` from the CLI), `--input` wins, the `pattern:` check still applies, rows carry `inputs_from`, `workflow show --json` marks `fills_from_branch`
- `lib/workspace/commands/workflow_start.rb` — `workflow start [ID] [REF | --prompt]`: `here:` (a `Here` of workspace, path and pane, given by `go`) runs the ref in that checkout through `Workflow#run` instead of making one, refusing `branch_exists` when the plan is for another checkout; with no ID, takes it from `WorkflowDefaults` for the ref's kind (`no_default_workflow`, `details.kind`/`ref`/`known`, before `workflow_needs_claude`); a lone word that is not `WorkflowCatalog#known?` is the ref, and a branch-shaped one with a default set starts with a `Warning:` (also in `results[0].warnings`; a ticket-shaped word does not warn), but beside `--prompt` stays `unknown_workflow`; reads the ref and ticket, seeds inputs and preflights (the tree of a reused or adopted checkout too, and the planned path of a new worktree for `unsafe_checkout_path`) before `start` makes anything; refuses `fork_pull_request` first (`details.reason`): a pull request unless `cross_repository` is exactly false and its base is origin's or upstream's repository (an unreadable one always refused), a reused, adopted or local branch whose git config tracks another repository, or a `pr-N` branch holding another pull request (its `branch.pr-N.workspace-pr`, else a `#N` read); a bare `#N` is checked out as the `owner/repo#N` that `gh pr view` read; seeds `task` and guards inputs through `WorkflowSeed`, and does not fill from the branch (`workflow run` does)
- `lib/workspace/workflow_inputs.rb` — A module, no instances: `WorkflowInputs.check(data, inputs)` is the pure check of the inputs given to a workflow against its definition hash (unknown name is a `UsageError`, `input_required`, `invalid_input` for a value past `INPUT_VALUE_LIMIT` or missing its `pattern:`), answering every declared input's value; `.check_patterns` is the pattern check alone
- `lib/workspace/workflow_alerts.rb` — `alerts.workflow` events (`gate`, `failed`, `stalled`, `finished`) through `Notifier`: `#marks(run)` is read inside `WorkflowRunChange#call` before and after a change, `#fire` after the lock is given up sends only what the change newly set; env values from the run file escaped, `next_action` never passed; a problem is a stderr line, never an error
- `lib/workspace/run_liveness.rb` — A run is alive while `~/.local/state/workspace/.workflows/runs/<id>.json` exists and its `state` is not `completed`, `failed` or `cancelled`
- `lib/workspace/run_resources.rb` — Holds a workflow step's `uses:` for the run: resolves the names (`dev-env` is `devenv`, `edit` is refused), acquires through `LockStore#acquire_run` without blocking, releases; `WorkflowEngine` is its caller
- `lib/workspace/workflow_review_spec.rb` — `WorkflowReviewSpec`, the `reviewers:` and step `review:` parts of a definition: `#reviewers(raw, inputs)` (the name `summary` is reserved, `RESERVED_NAMES`), `#review(value, where, inputs)` (a bare list is `from:`; defaults need = from.size, max_rounds 6, timeout 30m, context fresh, notify true; a null on a key with a default is a problem, `subject`/`revision` null means none) and `#check(steps, reviewers)` (unknown reviewer, `need`/`must` bounds, repeats); problems go to the `report` callable and the helpers come from `WorkflowDefinition`, which reads absence as none through `.reviewers`/`.review`; inert, nothing in a run acts on it yet
- `lib/workspace/workflow_definition.rb` — One workflow definition (YAML): checks every key, `use_when:` (one line) and `applies_to:` (ref kinds; `Commands::WorkflowStart` refuses another kind with `workflow_not_for_ref` unless `--force`, read through `.use_when`/`.applies_to`), an input's `pattern:` (whole-value regexp, compiled and at most 300 characters; `WorkflowEngine#check_input_patterns` (called by `check_inputs`) refuses a set value that misses it as `invalid_input`), collects every problem (`invalid_workflow`), fills defaults (a step's `guard:` is `unchanged` or `config`); `#to_h` is the copy a run keeps; `.render` fills `{{placeholders}}`; `#resolved_sha256` (what a run records as `definition_sha256`; covers the parents' text) and `#parents` serve `extends:`, which `WorkflowExtends` resolves before the checks; `#warnings` (never an error: `step_without_proof`, `on_timeout_without_timeout`, `on_fail_exceeds_max_attempts`, each `on_fail` weighed alone against `max_attempts`); `.command_needs` lists the project commands its steps use, which `WorkflowEngine#check_commands` and `WorkflowLint` share
- `lib/workspace/workflow_extends.rb` — `WorkflowExtends#resolve(raw)`, the `extends:` half of a definition: looks the parent up through the catalog (`below:` the asker's own source when the id is the same, so a user's `rpiv` can extend the preset `rpiv`), has it parsed and checked as a definition of its own (a fault is `failure`: `extends ID (PATH): ...`, reported alone, nothing else of the child judged; a cycle is by file, a chain over 4 parents is refused), then lays the child over its mapping (`inputs` merge by name, `replace:` swaps whole steps in place, `steps:` adds, each `after:` a step); its own faults against a good parent are `problems`; `#parents` lists them nearest first with the sha256 of each file's text
- `lib/workspace/workflow_lint.rb` — `WorkflowLint#call(definition, cwd:)`, behind `workflow validate`: the checks that need the person's setup, as warnings (`unknown_pack` for the default packs, the workflow's and each step's `include:`, with a later step worded as stopping the run since `start` reads only the first; `command_unset` for a `status:`/`require: command:` the project lacks, hinted `--name` for a workspace and `--scope global` otherwise) and `not_checked` entries when the current directory is not in a git checkout or the project's config can't be parsed (`commands_not_checked`); an invalid pack name (`UsageError`) is always a warning; `Commands::Workflow` requires it, and text output escapes through `TerminalText`
- `lib/workspace/workflow_defaults.rb` — `WorkflowDefaults#id_for(kind, workspace:)` (`#lookup` adds the key and layer): the id config names for a ref kind (`jira`, `github_pr`, `github_issue`, `branch`, `prompt`): `workflows.by_ref.<kind>`, then `workflows.default`, through `ConfigResolver` (a nil workspace reads the global file alone); a stored value comes back as text unchecked; `WorkflowStart` passes the project's workspace, so a worktree's own setting is not read; `config validate` warns `unknown_default_workflow` on an id the catalog does not know
- `lib/workspace/workflow_router.rb` — `WorkflowRouter#route(kind:, workspace:, ref:, force:)`, behind `workflow start --ref REF`: the kind from `StartRef`, then `WorkflowDefaults#lookup` (`workflows.by_ref.<kind>`, then `workflows.default`; no worktree file, the worktree does not exist yet), else the one valid definition whose `applies_to` lists the kind or is unset; several or none is `no_default_workflow` (the fits listed with `use_when`; `#unrouted` gives a start with no id and no key the same details), a default that is not an id, names no valid definition or leaves out the kind (unless `force`) is `invalid_workflow_default`; `WorkflowStart#route_ref` prints the `Routing ...` line through the output gate and adds `routed` to the row
- `lib/workspace/workflow_catalog.rb` — `#known?(id, project:)` and `#known_ids(project:)` say which ids resolve; finds a definition by id (`#parent(id, below:, project:)` is the lookup `extends:` uses, project first, so a project file can extend the user's or the preset's of the id it hides; `#extended_by(id)` (every project's directory too) names the definitions that extend an id, for the warning `workflow add|update|remove` give): for a `project:` (`WorkflowCatalog.project_of` maps a worktree workspace to its parent), `~/.config/workspace/projects/NAME/workflows/` (`Config#project_workflows_dir`, nil for a name that is not one safe directory name), then `~/.config/workspace/workflows/`, then the presets in `lib/workflows/` (`rpiv`, `rpiv-auto-approve`, `pr-feedback`, `investigate`, `explore`)
- `lib/workspace/workflow_project.rb` — `WorkflowProject`, the one answer to which project's workflow definitions a command reads first, shared by `show`, `validate`, `render`, `run`, `add`, `update`, `remove` (through `CLI#workflow_project`) and `workflow start` (`#for_directory(dir)`: the marker, then the state's active roots, then the checkout named as `start` names it; `#for_workspace(name)`: `unknown_workspace` for a name with no config). A `.workspace-project` marker counts only when the user's config ties that project to the checkout (`project_root_for`'s checkout has the same toplevel or git common dir), else nil with a stderr warning; a project name that can't be a directory name warns; `ProjectDetector#detect_from_roots` is its read of the state alone
- `lib/workspace/workflow_run.rb` — `WorkflowRun`, a frozen value over a stored run Hash, with `Step`, `Attempt` and `Summary`: `.from_h(hash)` (a WorkflowRun is returned as it is; else a deep frozen copy, or the Hash itself when already frozen; `#with_attempt(step_id, attempt)` is a new run with the step's attempt of the same n replaced, or the attempt appended when the step has none with that n, `#summary(reads_plan_again:)` is the view for files outside workflow; `Park`, `Backoff`, `BudgetHold` and `SweepMarks` are the same kind of value over `parked`, `backoff`, `budget_hold` and `sweep` (`from_h`/`to_h` and readers; the run's own readers of those four still return the raw Hash, which the existing specs read as one, and nothing builds the values yet); `#with_attempt`, `#with_park(request, id:, requested_at:, expires_at:, retries:)`, `#drop_park` (a parked note moves to the pending context as `.resume_note`), `#with_paused(since:, by:, text: nil)` and `#drop_paused` (the `paused` reader returns the stored `{"since","by","text"}` Hash) are its change methods, each returning a new run; `Commands::Workflow` reads a stored run through it (`@store.run`, `.to_h` where it hands a Hash to the engine, audit or run-files readers); `WorkflowStatus` (`@store.going`/`finished`/`run`; `#in_project?` takes either), `WorkflowAttempts#read` and `WorkflowStats` read a stored run through it, passing `.to_h` to the engine, budget and gate-note helpers that still take a Hash; `WorkflowSweep` (`@store.run`/`going`), `WorkflowRequire#check`, `WorkflowAlerts`, `WorkflowDeny`, `WorkflowGateNote` and `WorkflowSimulator` read a run through it too (a Hash or a WorkflowRun in, coerced at the entry; `.to_h` to the engine statics); fixtures in `spec/fixtures/workflow_runs/` (simulator output, some with keys added or removed by hand); `Step#review_held?`, `#review_stopped?` and `#review_live?` read a reviewing step's stored round (held: a `held` mark; stopped: `ended_at`; live: reviewing, neither held nor stopped, delivery not failed), read by `WorkflowStatus`.
- `lib/workspace/workflow_run_store.rb` — Run files under `~/.local/state/workspace/.workflows/`: `runs/<id>.json` and `<id>.events.jsonl` while a run is going (what `RunLiveness` reads), `archive/` once finished; `#stamp` (16 hex digits of the runs directory's SHA-256) is what `WorkflowReviewRound` stamps a review window with; `#change(id, nonblocking:) { |run| new_run }` is the one way a run changes, under the run's own flock: it stores the block's run (a nil return changes nothing: the run as read is stored) and returns nil when `nonblocking` finds the run busy; its `after_write:` callable is given the run as stored once it is written and before a finished run is archived (so the lines it writes move to the archive with the run, and none is lost when the archive move fails), while the lock is still held, and is skipped when the block or the write raises, which is how `WorkflowRunChange` writes a change's queued history lines after the run and under the lock; `#record_event` writes `ts` with millisecond resolution (`iso8601(3)`); `#run`, `#going`, `#finished`, `#on_checkout`, `#going?(id)`, `#parked_on(pane, except:, now:)` and `#backoff_on(pane, except:, same_pane:)` (the engine's pane and checkout occupancy reads) return frozen `WorkflowRun` values; it has no Hash methods (specs read and edit runs through `RunFileReads`); `WorkflowRunChange#call` writes through `#change` `#stamp` hashes the runs directory's real path (links resolved up to the deepest part that exists), so a symlinked state directory stamps alike; `#stamps` adds the digest of the path as written, which `WorkflowReviewOrphans` also takes as this store's.
