# Panes and session monitor

Tmux panes, the session monitor and its pane_* helpers, typing safety and screen reading. Full per-file detail, moved verbatim from `.claude/CLAUDE.md`; the one-line index there links here.

- `lib/workspace/tmux.rb` — Tmux session management; `#config_session_name` reads a config's `name:` line as YAML (else the text after the key), the name as the file writes it (`rename` rewrites that line, so `RenamePlan` and `NameMigration` use it); `#session_name_for` is the one name tmux stores for it (`.stored_session_name` of that: `.` and `:` as `_`), so every lookup against `#sessions` or `-t` target uses it with no conversion at the caller (`WorkspaceStoreRename` and `RenamePlan` convert the raw names they hold; the relauncher converts the pane's); `#session_name_for_pane(pane_id, project:)` asks the project's custom socket; `#client_session_name(tmux_env)` is the session whose id `$TMUX`'s third field names (`display-message -p -t '$N'` on its socket), nil for a malformed `$TMUX`; `#capture_screen_styled` reads a pane with its styling (`capture-pane -e`) for `StyledScreen`; `#capture_screen_scrollback` reads the same plus up to `SCROLLBACK_ROWS` (5) rows of history in one tmux call (`display-message` of `history_size`, `;`, `capture-pane -e -p -S -5`) and returns a frozen `StyledCapture` (`raw`, `history_rows`), nil when tmux fails, so readers can tell the leading history rows from the visible screen; `#pane_pid(pane_id)` is the pane process's pid, which `LockHolder` reads through its `tmux:`; `#open_window(..., store:)` also sets `REVIEW_STORE_OPTION` (`@workspace-review-store`) and `#review_windows` answers it as `:store`; `#server_pid_for_session(session, timeout:)` (the pid of the server that has the session) and `#renumber_windows?(session = nil, timeout:)` (through `TimedProcess` with a timeout) (the global option, or a session's own; nil when tmux can't say or the session sets none) `#mark_review_window(window, mark)` moves a window's `@workspace-review` mark and reads it back (a later round carrying over the window an earlier one left). `#pane_details(..., timeout:)`, `#review_windows(session, timeout:)` (raise `Timeout::Error` past it) and `#kill_window(target, timeout:)` (false past it) go through `TimedProcess` when given a timeout, else `Open3` as before; `#session_name_for_pane(pane, project:, strict: false)` raises the bounded call's `Workspace::Error` with `strict` (`WorkflowPanes#pane_gone?` passes it, so a wedged server is never a gone pane).
- `lib/workspace/styled_screen.rb` — `StyledScreen.parse(raw)`: a styled capture read per character, so `#faint?(line, column)` tells Claude Code's grey suggestion (SGR 2) from a typed draft; `#text` is the plain screen; it also takes a capture that answers `raw` and `history_rows`, whose first rows are scrollback: `#history_rows`, `#visible_lines` (the one row split, history dropped) and `#input_box(pattern)` (the last match of the pattern, only when its last character is on a visible row, never an earlier match) are the readers of it; `#proven?(line)` is false for a line with an escape it could not account for (a shift character, an unknown escape, a reverse-video cell without faint), which leaves only that line unproven and keeps today's refusal
- `lib/workspace/typing_safety.rb` — The one test of whether text may be typed into a pane: the agent's state, an open `AskUserQuestion` (`question_open`), a dialog, and an input line that holds a draft (`input_not_empty`); given a `StyledScreen`, an input drawn entirely faint on every proven line counts as empty; `PromptTyper` and `IdlePromptCheck` go through it
- `lib/workspace/idle_prompt_check.rb` — `IdlePromptCheck#refusal(facts, styled_capture)`: `TypingSafety` plus no busy row (a spinner row, `esc to interrupt`, `Retrying in`) within 16 rows above the input box, counting only the rows below the last finished-turn line (`DONE_ROW`, `✻ Brewed for 57s · done 12:51 PM`), so a finished reply that quotes the wording does not read busy; nil means the box is empty and nothing is running. `AgentRestart` (as `screen_ready:`) and `WorkflowPanes` read the screen only through it
- `lib/workspace/pane_locator.rb` — Strict pane resolver for `agent-run send`, `focus --pane` and `ask answer --deliver`: only a pane id or `window.pane`, and only a pane of the workspace's own tmux session
- `lib/workspace/pane_bindings.rb` — `bindings.json`: tmux pane id to the run, review or play it works on, with the session it was made in and the `packs` its agent was sent (a reviewer's `direct: true` for a direct review round, stored only when true); `session-event` prints it, and the packs composed again, as `additionalContext` on SessionStart; `#move` carries bindings to the panes `restore` resumes in; `#rename_workspace(from:, to:)` rewrites the workspace and session in each binding for `rename`; `#unbind_all(kind, id, role:, pane:)` removes a subject's bindings, of one role and one pane id when given (`WorkflowPanes#unbind(pane:)`, a review delivery's own pane)
- `lib/workspace/pane_dispatch.rb` — The pane steps `plan start` and `spine start` share: the daemon's panes (`no_daemon`), the main agent pane (never a review-window pane nor one with a live `reflection` binding, through `Commands::Binding#reflecting`), the `pane_busy` and `no_agent_pane` refusals, `#refuse_bound` (and `#owned`, `#bound_error`) for the `pane_bound_to_run` refusal of a pane a going run owns, `#spawn` (split, start the agent, wait for that pane), `#await_ready(name, pane, kind, window:, keep:)` (a pane made elsewhere; closes it, or its `window`, when never ready, nothing with `keep`), typing, and `#bind_play` (keeps a run or review binding, adds packs to a play binding)
- `lib/workspace/question_closed_check.rb` — `QuestionClosedCheck#reading(kind, styled_capture)`: a digest when the screen proves a question dialog gone (the input box whole and empty, no busy row, no dialog hint under it), nil otherwise; no captured dialog form passes (`spec/fixtures/claude_screens/question_*`). `HOLD` is how long `SessionMonitor` wants one reading held
- `lib/workspace/session_monitor.rb` — Per-pane coding-agent and sub-agent state (working/idle/waiting), keyed on tmux pane id; fires alerts; on each scan closes a question tool left open by Esc (which sends no hook), and the main agent's wait with it, once `QuestionClosedCheck`'s reading has held with no hook event; `#main_turn_evidence` and the snapshot fields `activity_state`, `main_turn_over_since`, `transcript_path`, `open_tools`, and the top-level `features` (`parked_resume`) say whether a turn is proven over and whether this daemon can release a parked resume; `PostToolUseFailure` closes a tool like `PostToolUse`; `#snapshot` panes carry `waits` (each open wait by agent id); `#record` applies a hook event through `PaneEvents` under its lock; states, their times and the logged state changes come from `PaneStates`; which alerts are due, their env and logged data come from `PaneAlerts`, and `#send_alerts` marks each one sent by `[pane_id, wait_key]` on the pane under that id, never on a Hash read before the notifier ran (the stale flag and failed-`ps` streak stay on the monitor, passed as `stale:`); its scan reads through `PaneScanner` (`scanner:`, nil builds one over the monitor's `tmux`, `process_tree`, `detector`, `question_check` and `event_log`); `#snapshot` reads the task through `PaneView#task` before its lock and builds each row through `PaneView#present` inside it (the scan refreshes the label and context caches through `PaneView#refresh`), the document through `PaneView.document` `#rescan_unclassified` re-reads in one pass, under no scan slot, every listed pane not yet named Claude Code and not a review pane; the `sessions` request's `rescan` flag runs it.
- `lib/workspace/pane_events.rb` — `PaneEvents`, the monitor's hook-event reducer over a symbol-keyed pane Hash: `.apply(pane, event, now:)` (session, label source, open tools, waits, permission requests, done mark, failed turn, sub-agents; answers a new pane, leaving the one given and its nested collections unchanged), `.new_pane(pane_id)`, and `.clear_waiting`/`.resumed_wait(now:)` that the scan shares; `MAIN_ACTIVITY` names `#main_turn_evidence`'s reasons; no lock, clock or I/O, called only by `SessionMonitor` inside its lock; spec `spec/unit/workspace/pane_events_spec.rb` over plain Hashes; flat until T50
- `lib/workspace/pane_states.rb` — `PaneStates`, the monitor's state rules as module functions over a symbol-keyed pane Hash, `now` and `idle_after` passed in: `state_of` (working/idle/waiting), `reported_state` (`done` first), `oldest_wait`, `since_for`, `changed_by_for` (the input a state comes from), `fresh_since` (`#fresh_since` for one pane), `main_turn_missing` (`#main_turn_evidence`'s reason), and `state_change`/`gone_change` (the `agent_state` data, writing only the pane's `logged_state`/`state_since`); `NOT_AGENTS`, `GONE_STATES`; no lock, clock or I/O, called only by `SessionMonitor` inside its lock; spec `spec/unit/workspace/pane_states_spec.rb` over plain Hashes; flat until T50
- `lib/workspace/pane_alerts.rb` — `PaneAlerts`, the monitor's alert rules as module functions over a symbol-keyed pane Hash: `due(pane, now, session_name:, idle_alert_after:, stale:)` (each unalerted wait, else one idle alert per quiet stretch; none for `NOT_AGENTS`) answering `Due` values (`key` `[pane_id, wait_key]`, `IDLE` or the wait's agent id; `value`, `env`, `logged`), `mark(pane, wait_key, value)` (a wait only while it is the one that began at `value`; answers a new pane, which the monitor stores under the id), `restore_waits`/`logged_time` (the marks a restart reads back; `restore_waits` answers a new pane too), `env` (the `WORKSPACE_ALERT_*` environment, `handoff_stalled` too), `idle_data`/`waiting_data`; the one writer of alert marks; `PaneScanner` keeps the alert history it reads from the event log; no lock, clock or I/O, called by `SessionMonitor` inside its lock and by `PaneScanner#refresh`; spec `spec/unit/workspace/pane_alerts_spec.rb` over plain Hashes; flat until T50
- `lib/workspace/pane_screen_rules.rb` — `PaneScreenRules`, the scan's screen rules as module functions over a symbol-keyed pane Hash and the text a capture gave: `end_answered_permission_waits` (a bound permission wait ends once Claude Code's ready prompt is back at the bottom, not on an `AskUserQuestion` menu row), `screen_wait` (a provider's waiting screen opens or drops the `screen` wait), `question_tools` and `hold_question` (one `QuestionClosedCheck` reading held `HOLD` seconds with no hook event closes the question tools, the main agent's wait and request, and ends the turn; answers whether it closed); no lock, clock or I/O, called only by `PaneScanner` inside the monitor's lock; spec `spec/unit/workspace/pane_screen_rules_spec.rb` over plain Hashes; flat until T50
- `lib/workspace/pane_scanner.rb` — `PaneScanner` (`tmux:, process_tree:, session_name:, providers:, detector:, question_check:, idle_after:, clock:, logger:, error_output:, event_log:, project:`), the reads of `SessionMonitor`'s scan: `#pane_details`, `#process_snapshot` (raises `Workspace::Error`; the monitor counts the failed streak), `#load_history` (each pane's last logged state and alerts, read once; it owns that alert history, and the marks it restores go through `PaneAlerts`) and `#refresh(pane, detail, tree, now)` (answers the pane the monitor stores under its id: changed in place, or a new one when a restored alert mark is taken up; the logged state taken up for the same pane pid, tmux fields, the agent through `detector`, activity from a `capture_pane` digest, then `PaneScreenRules`, the styled capture only with a question tool open, a close reported on `error_output`); holds no panes and takes no lock, the monitor calls `#refresh` inside its own; spec `spec/unit/workspace/pane_scanner_spec.rb` (its own examples, and the question and permission-screen examples moved from the monitor spec, read through `SessionMonitor`); flat until T50
- `lib/workspace/pane_view.rb` — `PaneView`, what `SessionMonitor#snapshot` shows: the pure rules as class methods over a symbol-keyed pane Hash and plain values, `.row(pane, now, idle_after:, providers:, label:, context:)` (the `sessions --json` row, with `state_changed_by`, `turn_failed_kind` and `user_prompt_at` (the pane's `last_user_prompt_at`, milliseconds), built as new Hashes in today's key order; a shell pane carries no context, tool status or hook mode fields), `.document` (panes by index), `.task_row` (the task with its derived `status`) and `.task_title`; the instance (`context_reader:, label_reader:, task_reader:, providers:, idle_after:, poll_interval:, project:, logger:`) holds the readers and the scan-time caches (`CACHE_GRACE_INTERVALS`): `#task` (outside the lock, a failing reader is no task), `#present(pane, now, task, scanned_at:)` and `#refresh(pane, now)`, called by the monitor inside its lock and writing only the pane's `label_cache`/`context_cache`; spec `spec/unit/workspace/pane_view_spec.rb` over plain Hashes (the cache examples stay in the monitor spec); flat until T50
- `lib/workspace/pane.rb` — `Pane.new(tmux:, session_name:, id:, row: nil)`: one tmux pane of one session as the agent daemon's desks see it (`capture`, `capture_styled`, `deliver(text, enter:)`, `send_key`, `details`, `server_pid`, `start_command`, `session_gone?`), over `Tmux`; the id must match `%N` (`ArgumentError`); a `row:` already read answers the first `details` call. Not `TmuxPane` (the resolver of a pane spec typed on a command line); both exist. No callers yet
- `lib/workspace/pane_factory.rb` — `PaneFactory.new(tmux:, session_name:).call(pane_id)` (lists the panes) and `#for(pane_id, row: nil)` (a Pane built with no tmux call, `:gone` for a non-pane id; where a desk reads a screen or types, so no path makes a call it did not make before panes; `spec/unit/workspace/pane_call_counts_spec.rb` pins the calls with `RecordingFakeTmux`): a `Pane` holding the row found, `:gone` (a non-String id without listing, or a String the session does not list) or `:unlisted` (tmux listed no pane at all); `FakePane` and `FakePaneFactory` (`spec/support/fakes/fake_pane.rb`, over `FakeTmux`) are held to both by `fake_contract_spec` and `pane_contract_spec`
- `lib/workspace/pane_locks.rb` — `PaneLocks#for(pane_id)`: one Mutex per tmux pane id, made on first use and the same on every call; `PromptQueueDesk` asks it whether a pane's delivery lock is taken
- `lib/workspace/session_monitor_builder.rb` — Builds the `SessionMonitor` for one workspace from the daemon's settings (alert, scan and agent-command config read once at `#call`); built in `build_cli` and given to `Workspace.build_agentd_parts` as `session_monitor_factory:`; `scan_slots:` is required (the limiter `build_cli` shares with the context reader; nil scans ungated); `notifier_factory:` and `ps_timeout:` default to a `Notifier` and the process tree's default; `monitor_factory:` and `process_tree_factory:` replace the parts
- `lib/workspace/process_tree.rb` — One-shot `ps` snapshot with parent/child lookups

- `lib/workspace/agent_labels.rb` — Names the coding agent each tmux pane runs, by the label `workspace sessions` shows in its TITLE column ("Claude Code", "Codex"). Agents are recognized the way {SessionMonitor} and {AgentReadiness} do, from a pane's command and the process table, over the same configured providers.
- `lib/workspace/commands/capture.rb` — Reads a tmux pane's scrollback buffer and writes it to output.
- `lib/workspace/commands/sessions.rb` — Shows which panes in a workspace are running a coding agent, whether each is working, idle, or waiting on a person, and what sub-agents they have started. The daemon holds the state; this command only asks for it. That keeps one code path behind both the table and `--json`, so what a future UI reads is exactly what the table shows.
- `lib/workspace/commands/wait_until_content.rb` — Polls a tmux pane's scrollback until it contains a target string, then execs a follow-up command so it replaces this process and owns the terminal (direct Ctrl-C, untouched STDIN/STDOUT/STDERR). Port of the standalone wait-until-content script. By default it matches against the last --lines lines of the pane's scrollback, so content that was already present matches immediately. With since_start: true it takes a baseline of the full scrollback when it starts and only matches content written after that point, anchoring on the baseline content itself (see #post_start_lines) rather than on a line offset, which churn at the history limit or a mid-wait clear-history defeats. The pane spec is resolved once, at start, to the pane's tmux pane id, and every poll re-resolves by that id: a :bottom/index/title selector cannot silently switch to a renumbered pane when the target closes — the id stops resolving and the wait errors out.
- `lib/workspace/session_workspace.rb` — The one map from a tmux session to the workspace whose agentd owns it. A worktree workspace's session (`proj-wt-feat`) is not named like the workspace (`proj.worktree-feat`) agentd binds its socket for, so the name cannot be read off the session. Launch records it on the session as the user option {OPTION}; this reads that back. A session started before that (no option) is looked up in the tmuxinator configs, and one no config names is not a workspace session at all (nil).
- `lib/workspace/tmux_pane.rb` — Resolves a pane specification to a tmux pane index. Spec forms accepted: nil / :bottom / "bottom" → last pane in the window Integer → zero-based pane index (validated against live panes) String matching /\A\d+\z/ → same as Integer String matching /\A\d+\.\d+\z/ → "window.pane" (as shown by `workspace sessions`/tmux); window overrides the window: kwarg String matching /\A%\d+\z/ → a tmux pane id (as shown by `workspace sessions --json`'s pane_id); searched across the whole session, so it resolves regardless of window Any other String → case-insensitive title search via Tmux#find_pane_by_title, then against the agent label `workspace sessions` shows in TITLE ("Claude Code", "Codex"), since an agent often rewrites its own pane title (Claude Code sets "✳ <task name>") A title search tries the raw tmux pane title first, then the agent label, each as a case-insensitive substring; the first matching pane (lowest index) wins. Use "window.pane" or a "%id" to be exact.
- `lib/workspace/transcript_label.rb` — Reads the title and last prompt Claude Code keeps in a session's transcript, so `sessions --json` can label a pane by what it is doing. Claude rewrites the `ai-title` line as the session goes, and writes a `last-prompt` line each turn, so the last of each near the end of the file is the current one. Only those two JSON fields are read; the rest of the transcript is never kept. A transcript can run to megabytes, so only the tail is read, and the result is cached until the file changes.
- `lib/workspace/scan_slot_limiter.rb` — Bounds how many session monitors scan at once, machine-wide. Every running `workspace agentd` daemon polls its tmux session on a fixed interval, and each poll spawns a handful of processes (`tmux list-panes`, one `ps` snapshot, one `tmux capture-pane` per pane). With many daemons on one machine those spawns stack up around the clock, so scans take turns instead: a monitor holds one of N slot files for the duration of a scan, and one that can't take a slot skips that tick — it never waits. Under load the effective per-daemon interval becomes roughly `interval × ceil(daemons / limit)`. A slot is a plain file taken with a non-blocking exclusive flock, which the kernel releases when the fd closes or the holder dies, so a crashed daemon never strands a slot. The slot is re-entrant per thread and directory: a call made while this thread already holds a slot for this limiter's directory runs under the hold it already has. flock is held per open fd, and a second non-blocking lock on another fd of the same file fails even from the process holding the first one, so a nested call — a monitor's scan reading a pane through a context reader whose own limiter works the same directory — would always read every slot as busy without it.
- `lib/workspace/commands/layout.rb` — Saves, restores, and lists tmux pane layouts for workspace projects. Named layouts are stored in per-project config YAML; ephemeral snapshots (like _before_resize) are stored in state.json.
- `lib/workspace/commands/resize.rb` — Resizes tmux panes for a running workspace project. Accepts a comma-separated spec of sizes (rows or percentages).
- `lib/workspace/commands/statusline.rb` — `workspace statusline` — installed as Claude Code's `statusLine` command. Claude pipes one JSON payload on stdin every render and prints whatever this writes to stdout. Two jobs, always in this order: 1. Record the reading: `context_window.used_percentage`, keyed on `$TMUX_PANE` (falling back to `$CLAUDE_PID` when TMUX_PANE isn't set), so `sessions --json` can see it later without Claude having to render again. Recorded even if rendering itself then fails. Right after `/clear`, Claude renders with `used_percentage` as JSON null (and a new `session_id`); that's still recorded, as a reading with a nil pct, so the new session is visible to readers even before Claude reports a real percentage. Only a present-but-invalid value (a string, a negative number, one over 100) is dropped. The same call records `cost.total_cost_usd`, `cost.total_duration_ms`, and `model.display_name` (each nil when absent or the wrong type). 2. Print a line: a `statusline.command` in the global config gets the same stdin and its stdout is printed as-is, time-bounded so a slow or hung delegate can't freeze Claude's status bar; otherwise (or on delegate failure/timeout) the built-in {Workspace::StatuslineRenderer} runs instead. This runs on every render of every pane, so it must never crash the status bar: bad or empty JSON, a storage error, or a delegate failure all still print *something* and exit 0.
- `lib/workspace/context_reasons.rb` — Shared reason strings and fix hint for a coding-agent pane whose context usage percentage can't be determined right now. `sessions --json` and `workspace handoff check` both surface these, so they live in one place rather than being duplicated (and drifting) between the two.
- `lib/workspace/context_store.rb` — Persists the most recent context-window reading for each tmux pane running `workspace statusline`, so `sessions --json` and `workspace handoff check` can report it without depending on Claude's status line having just rendered. Keyed on `$TMUX_PANE` — the same identity `workspace session-event` and {Workspace::SessionMonitor} use — because pane indices shift as panes split and close. A status-line process that started without `TMUX_PANE` set (it happens; see the class docs on {Workspace::Commands::Statusline}) is recorded under its `CLAUDE_PID` instead, so a pane can still be matched up via its agent process id. Guarded by `flock` on a sentinel file, matching {Workspace::LockStore} and {Workspace::Commands::Config}: never locked on the JSON file itself, since it's rewritten via tmp-file-then-rename on every write.
- `lib/workspace/statusline_renderer.rb` — Builds Claude Code's status line: model, directory, git branch, a context usage bar, session cost, and turn duration. Ports `~/.claude/statusline-command.sh`, minus the usage API call — that hit `https://api.anthropic.com`, and `workspace` never calls an external URL. Reads only the stdin JSON Claude Code passes to a `statusLine` command and local git; nothing here makes a network request.
- `lib/workspace/commands/restore.rb` — Brings back the coding-agent panes a reboot or a tmux restart took: reads the session ledger, recreates each recorded agent pane that is gone (however it was made, including one split by hand), and types the resume line into it from the session's directory (see {AgentResumeCommand}). A workspace whose tmux session is not running is launched first, through the block given to {#call}. The panes its config gives a command are left to the config; a pane that already runs an agent or another program is never typed into. Pane bindings follow their slot to the pane that now sits there.
- `lib/workspace/commands/send.rb` — Types into one named pane of a workspace's tmux session, straight through tmux (no agent daemon needed): either literal text, or tmux key names such as `Escape` or `C-c`. Backs `agent-run send`, and `ask answer --deliver`. The pane is always named by the caller and checked against the workspace's own session by {Workspace::PaneLocator} before anything is typed, so a wrong, ambiguous or stale reference is an error and never a different pane. Keys are checked against a known set before the first one is sent, so a typo can't type a word into the pane.
- `lib/workspace/commands/run.rb` — Sends a shell command to a specific pane in a running project's tmux session.
