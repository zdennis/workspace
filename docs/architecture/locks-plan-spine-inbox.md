# Locks, plan, spine, inbox

Locks and dev sessions, plan and spine files and commands, the inbox, asks, tasks and alerts. Full per-file detail, moved verbatim from `.claude/CLAUDE.md`; the one-line index there links here.

- `lib/workspace/spine_file.rb` — One spine file (a stage file or `goal.md`) read without following links, never failing: `PlanFile`'s frontmatter dialect plus `[a, b]` and indented `- a` lists, status aliases to the six canonical values, the `## Done when` checklist, `revision` (short SHA-256 of all bytes), `key_span`/`frontmatter_lines` for `spine set`, `check` (the opt-in and verdict that `spine verify` writes), warnings with codes
- `lib/workspace/spine_tree.rb` — Walks `spine/` in the notes dir (`<number>-<id>.md` stages, a folder named like a stage file for sub-stages, to 3 levels; the 64/24/96 limits); `Stage` holds the file, children, `rollup` and the dependency checks; `#find(path)`, `#to_h` is the `spine show --json` document
- `lib/workspace/spine_rollup.rb` — The one roll-up of a stage's children (`model.ts` `rollUp`) over each child's effective state (a folder-only child takes its own roll-up): `status` (all skipped is `skipped`), `done`, `total`, `counts` with `disputed`; `SpineTree::Stage#rollup` calls it
- `lib/workspace/commands/spine.rb` — `spine show [WS] [--name WS] [--json]`: the notes dir through `Commands::Notes#info`, then `SpineTree`; read-only, a bad file is a warning, never an error; `#stage!` and `#write_one` (one write under the spine lock, after a caller check) serve `spine start`
- `lib/workspace/spine_inferred.rb` — Port of the app's `inferred.ts`: with no `spine/`, `spine show --evaluate` lists Research to Ship (Ship for a linked worktree) under `inferred`, from the plan, the workspace's runs still going (a run with a research/plan/implement/verify step outranks the plan), the review agent and the pull request; `.stages` is the pure rules, `#infer` adds the run files and the checkout layout to `SpineFacts`' one read
- `lib/workspace/commands/spine_start.rb` — `spine start [WS] PATH [--pane P \| --spawn KIND] [--play REF] [--if-revision REV]`: refuses from the file (`stage_done`, `stage_waiting` by file statuses, `stale_revision`) and the panes (`stage_owned`, `pane_busy`) through `PaneDispatch`, then writes `in_progress` and the owner under the spine lock, types the brief (play, `spine` pack, stage path and file), binds the pane; only a failed delivery leaves the file written, with a reset hint
- `lib/workspace/plan_file.rb` — The parser for a workspace's `IMPLEMENTATION_PLAN.md` (`PlanFile.parse(text)`, `PlanFile.read(path)`; nil when the file is missing): frontmatter, the `- [S] ID Title` tasks under `## Tasks`, `counts`, `percent`, `current`, `warnings`; it never fails. `PlanFile.set_status`, `.set_owner_pane` and `.set_task` are the only writers of the file: one frontmatter line, or one task line's box and `<!-- owner: %N -->` comment, through a temp file and rename, with one re-read and retry
- `lib/workspace/plan_state.rb` — `PlanState#derive` picks the one plan `state` (`empty`, `done`, `paused`, `stopped`, `waiting`, `working`, `blocked`, `stalled`, `idle`) from the parsed plan and the facts; `#row` builds the row `plan status --json` and, minus `tasks`, each member's `plan` in `snapshot` (from the snapshot's own reads)
- `lib/workspace/plan_config.rb` — Reads a project's `plan.stall_seconds`
- `lib/workspace/commands/plan.rb` — `plan status|path|show|init|pause|delete`; `status` takes its scope from `StatusScope` (this workspace, `--project [NAME]` or `--all`; `--file` and `--group` stay apart); `#rows(names:, all:, project:)` returns the rows, gathering the session, the owner pane's state and the open questions; `#start` is given a `launch:` callable by `CLI::PlanSpine` (launching is `CLI::Launcher#launch`) and otherwise types into the main agent pane and binds it to the play; `#start_task` sends one task to a named pane, a pane it splits and starts an agent in (`--spawn`: `MainAgent#spawn_command` picks the command, through `Commands::Run` and `AgentReadiness#wait(only_pane:)`), its owner or the main pane, then writes the owner onto the task line; `#pause(interrupt: true)` presses `AgentProvider#interrupt_keys` in the working owner panes; every change records `plan_changed`
- `lib/workspace/commands/plan_dispatch.rb` — `plan start [--task]` (launch, or type into a pane, bind it, write the owner onto the task line) and `#interrupt_owners` for `pause --interrupt`; `build_cli` wires it to `Commands::Plan` and `CLI::PlanSpine`
- `lib/workspace/plan_access.rb` — What the plan command objects share: the plan file's path, `no_plan`/`plan_done`, the `status:` write and `plan_changed`
- `lib/workspace/alert_config.rb` — Reads a project's `alerts.notify` and `alerts.idle_after`
- `lib/workspace/notifier.rb` — Runs the notify command in the background with a timeout, details in `WORKSPACE_ALERT_*` env vars
- `lib/workspace/inbox_store.rb` — Flock-guarded JSON file of one inbox scope (workspace, project or global) under `~/.local/state/workspace/.inbox/`; `add`, `upsert` (by `dedupe_key`), `list`, `find`, `update`, `transition`/`transition_by_key`; `#rescope(key:, name:)` rewrites the scope of every item for `rename`; a passed snooze or expiry reads as `open`/`dismissed` without writing
- `lib/workspace/commands/inbox.rb` — `inbox add|list|show|edit`: `add --link-run` stamps `links.step`/`links.attempt` from the run (`WorkflowRunStore#find`, null with a stderr line when the run isn't going in the item's workspace); `list --include-derived` marks each derived gate row `covered_by`; `add --note REL` (or `--from-json` `note`) points an item at a note in the workspace's notes dir, checked by `NotePath`; scope resolution (`--name`, `--project`, `--global`, else the cwd's workspace), input checks that refuse control characters and over-long or non-https text (`invalid_inbox_item`), and output with control characters escaped; stores come from an injected `store_factory`
- `lib/workspace/inbox_derived.rb` — The rows `inbox list --include-derived` works out and never stores: open asks, waiting panes (daemons read in parallel, each bounded), blocked or stalled plans, workflow gates and stuck locks, by workspace-ui's queue rules; a source that fails is a warning and no rows A stopped review round (`WorkflowTransitions::REVIEW_STOPS`) or a review pane's permission prompt (`details.role` `reviewer`) is a `workflow_waiting_you` row (`review_stop?`, `review_row`), since review panes get no pane row.
- `lib/workspace/inbox_acks.rb` — `.inbox/acks.json`: the derived rows acked or snoozed (`{id, fingerprint, acked_at[, until]}`), written like a scope file; `#filter` leaves out a row whose id and fingerprint match a live entry, writes drop old acks (30 days) and passed snoozes; `Commands::Inbox#ack`/`#snooze` read the current derived rows for the fingerprint
- `lib/workspace/ask_store.rb` — Flock-guarded append-only store for `workspace ask` questions, one `asks.json` per workspace under its XDG state dir
- `lib/workspace/task_store.rb` — Flock-guarded one-file-per-task store under `~/.local/state/workspace/.tasks/`: `start` creates, `#update(id, workspace:, branch:, path:)` rewrites a live task for `rename`, `finish`/`kill` archive (newest 200 kept); the task id is `WORKSPACE_TASK` in panes
- `lib/workspace/lock_namespace.rb` — Resolves the shared lock namespace (git common dir) from a cwd
- `lib/workspace/lock_holder.rb` — Identifies the calling agent's pid/start time and checks holder/waiter liveness; `#run_alive?` asks `RunLiveness` about a run holder; `tmux:` (optional) names the pane's process, none means the pane is not searched; `#holder_alive?(pid:, started:)` is `#alive?`, or with no start time recorded the pid running at all (a review round's delivery holder, through `WorkflowRoundHolder#alive?`)
- `lib/workspace/lock_store.rb` — Flock-guarded JSON lock store (acquire/release/status/clear), reaped on every op; `#acquire_run`/`#release_run` hold locks for a workflow run (`kind: "run"`, keyed on the run id, exempt from `release_all`, taken in sorted order), and `#delegate`/`#end_delegate`/`#keep_delegate` record the dev wrapper working under a run's hold; `LockStore.run?` is the one check for a run record; `#peek(name)` reads one lock as `status` shows it with no mkdir, flock, write or reap (for `rename --dry-run`); `#run_records` reads every `kind: run` holder and waiter with no mkdir, flock or write (for `doctor`); `renamer:` moves the temp file over `locks.json` (default `File.rename`)
- `lib/workspace/held_locks.rb` — The live locks of a repository the caller holds (its agent's pid and start time, a process lock from its pane, its bound run's), for `promote`'s `locks_held` warning; every live lock with `own: false` when the caller cannot be told
- `lib/workspace/bound_run.rb` — The run the calling pane is bound to (a non-stale `kind: run` binding of `$TMUX_PANE`); lets `dev up` and `lock acquire` tell the run's own agent from anyone else
- `lib/workspace/lock_config.rb` — Reads a project's `locks.idle_grace` (falls back to 5m with a warning)
- `lib/workspace/dev_session_release.rb` — On a `session-event` SessionEnd (never reason `clear`), finds a `devenv` lock record whose `started_by.session_id` is the session by reading the lock files, then starts `workspace dev __release SESSION` as its own process; `Commands::Dev#release_for_session` does the stop (unless `dev.release_on_session_end` is false, or anything cannot be read)
- `lib/workspace/lock_idle_tracker.rb` — Marks an agent's lock idle/active from `session-event` hooks, for idle takeover
- `lib/workspace/dev_events.rb` — Writes `dev_started` and `dev_stopped` (reasons `down`, `exit`, `reaped`, `forced`) to the event log; `DevRunner` writes the start and an exit on its own, `Commands::Dev` the stops it makes, and `LockStore`'s `on_reap` hook reports a dead wrapper to the agent daemon's `LockReaper`
- `lib/workspace/dev_runner.rb` — The `dev __run` wrapper: holds the `devenv` lock while the dev command runs on the pane's TTY, forwarding stop signals once to its process group; started from a run's pane while that run holds the lock, it is the run's delegate instead
- `lib/workspace/process_group_terminator.rb` — SIGTERM then SIGKILL for a lock holder's process group, after checking pid + start time
- `lib/workspace/process_holder_stopper.rb` — Stops a `kind: "process"` lock holder for `lock clear`/`dev down`, or keeps the lock naming it when the group can't be stopped; `#stop_group` does the stop alone, for a run's delegate
- `lib/workspace/dev_config.rb` — Reads a project's `dev:` block (`up`, `ready`, `stop_timeout`; `#configured?` and `#instructions?` decide the automatic `dev` pack), as written by `workspace config set`
- `lib/workspace/run_result_cleaner.rb` — Removes run files in `~/.workspace-runs` older than 7 days, never an in-progress run or a live session's; swept at most hourly from `RunResultStore#write`

- `lib/workspace/commands/ask.rb` — Records a question an unattended agent hits, along with the default it took, so the agent can keep going instead of blocking on a person. `ask` never reads stdin and returns once the question is on disk and any notify command has finished (or been stopped at its timeout); a human reviews and resolves open questions later with `ask list`/`ask answer`.
- `lib/workspace/commands/dev.rb` — Starts, stops, and inspects a repository's single dev environment, guarded by the repo-wide `devenv` lock. `up` opens a `devenv` tmux window running `workspace dev __run` (the {DevRunner} wrapper, which holds the lock for exactly as long as the dev command runs), waits for the wrapper to hold the lock, then waits for the configured `ready` probe. Every public method returns `{exit_code:}` so `CLI#cmd_dev` picks the process exit code. A workflow run can hold `devenv` for a step (see {RunResources}). The lock then says who may start the environment, not that one is running: `up` from the pane bound to that run starts the wrapper as the run's delegate, `down` stops the delegate and leaves the lock with the run, and everyone else queues behind the run with `up --wait`.
- `lib/workspace/commands/goal.rb` — `goal show [REF]` and `goal list`: where a goal is at each level (the goal, its journey stage, its workflow step, the agent's turn, the tool call), what it waits for and on whom. A goal is a workspace; a run id, task id, ticket key, URL or branch resolves to the workspace that holds it. It only combines reads that exist: {Workspace::Commands::Snapshot#document}'s member row (plan, spine or its inferred stage, panes, task, git, questions), {Workspace::WorkflowStatus#runs}, and the daemon's panes for the tool call; {Workspace::GoalState} holds the state rules; {Workspace::DeliveryFacts} reads the branch's push and merge state from local git. It writes nothing and makes no `gh` or network call. A level with nothing to show is null; a source that can't answer is null and a warning, never an error.
- `lib/workspace/commands/lock.rb` — Coordinates agents sharing a resource (first: edits to a shared worktree) through one flock-guarded lock store per repository. `acquire`, `release`, `status`, and `clear` are the whole public API, each returning `{exit_code:}` (and any command-specific fields) so `CLI#cmd_lock` can pick the process exit code without this class ever calling `exit` itself.
- `lib/workspace/commands/plan_task.rb` — `workspace plan task add|set-state|set-title|move`: changes one task line of a workspace's plan so people, agents and the app need not edit the Markdown by hand. Each verb goes through a {PlanFile} writer (temp file and rename, one re-read and retry), changes only the line it must, keeps owner comments, never renumbers, and refuses an id that is already used. Every verb takes `if_revision`: the `revision` that `plan status --json` reports. When the file has changed since, the verb refuses with `stale_revision` and writes nothing, so a caller acting on an old view cannot overwrite a newer one. The result carries the new `revision`. A verb that changes the file records `plan_changed` in the event log, and the agent daemon's plan watcher reports the new counts as `plan_progress`.
- `lib/workspace/commands/spine_init.rb` — `spine init`: copies a spine template (a library entry of kind `spine`) into the `spine/` folder of a workspace's notes directory, filling `{{WORKSPACE}}`, `{{BRANCH}}` and `{{TITLE}}`. It never overwrites: a `spine/` that is there already is `exists` and nothing is written. The folder is built beside `spine/` and renamed into place, so a reader sees all of it or none.
- `lib/workspace/goal_state.rb` — The goal's one `state`, who it waits on and the event that moves it on, from reads that already exist: the plan's own state ({Workspace::PlanState}, in the snapshot member's `plan.state`), the run's reason and flags ({Workspace::WorkflowStatus}), the pane's state and the member's spine counts. It reads and writes nothing. A paused run reads `waiting` on the person until `run_unpaused`.
- `lib/workspace/lock_audit_log.rb` — Append-only audit log for one lock namespace, written to `locks.jsonl` next to that namespace's `locks.json`. {LockStore} calls {#append} only after it has committed the `locks.json` write an event describes, while still holding its own flock, so lines land in the same order as those writes. Growth is bounded by simple size-based rotation: once the file would exceed +rotate_bytes+, it's renamed to `locks.jsonl.1` (replacing any previous one) and a fresh file is started, so at most two generations ever exist on disk. Once an append looks due to rotate, the re-check, rotation, and append run under an exclusive flock on a dedicated `locks.jsonl.lock`, since callers holding only a shared store flock (denies) could otherwise both rotate and clobber a whole generation. That lock is always taken after the store flock, never before, so the two can't deadlock.
- `lib/workspace/lock_enforcer.rb` — Denies an Edit/Write/MultiEdit/NotebookEdit tool call when this namespace's `edit` lock is held by another agent, and releases every lock this agent holds when its session ends or is cleared. Runs from `workspace session-event` on every `PreToolUse`, `SessionEnd` and `SessionStart` hook, so the common case — no lock store, or no `edit` hold anywhere — has to be nearly free: a plain file read across namespace directories, no `git` subprocess, before the real namespace is resolved. It never raises; enforcement fails open rather than blocking an edit on its own error.
- `lib/workspace/lock_reaper.rb` — Reaps crashed lock holders and waiters from the session-monitor daemon, so `workspace lock status` and `workspace sessions` stop showing a dead agent's hold even when no lock op comes along to reap it. It only runs {LockStore#reap}, the same pass every lock op starts with, so it can never drop a holder an op would keep: a kept `devenv` holder stays while its process group runs. The namespaces reaped are the ones the workspace's panes are working in.
- `lib/workspace/plan_progress_watcher.rb` — Watches one workspace's plan file and records `plan_progress` in the event log when its `## Tasks` checklist changes, however the file was edited (a plan verb, an agent, an editor). It stats the file on a short tick, parses it with {PlanFile} only when the file changed, and waits for the file to sit still for {SETTLE} seconds before writing one line, so a burst of edits is one event. A change that leaves every task as it was (prose, frontmatter) writes nothing.
- `lib/workspace/spine_config.rb` — Reads `spine.template` and `spine.auto`, as written by `workspace config set`: which spine template `spine init` and `start` use, and whether `start` runs `spine init` on its own. Both are layered global < project < worktree and read through {ConfigResolver}.
- `lib/workspace/spine_evaluator.rb` — The verdict on a workspace's stages: a port of the app's `src/core/spine/model.ts`, so the CLI and the app judge a stage alike. Each stage's file status is a claim; the gates it declares, its `## Done when` list and its sub-stages are the evidence. Evidence can hold a `completed` claim back (`disputed`), or say a stage not marked completed looks done (`looks_completed`), which never moves it. Pure: it reads only the {SpineTree} and a {Facts} value, and runs nothing. A fact that is nil was not read, and every gate that needs it is `unchecked`; `pending` and `unchecked` never dispute. A stage that has opted in to a check (see {SpineFile#check}) and claims `completed` reads `checking` until a verdict (no `passed` yet) and `check_failed` after a `failed` one. A dispute outranks both: evidence against the claim is shown first, and the check is still reported in `check`. Neither state is done, so `current`, `waits_on` and the roll-up hold the stage back.
- `lib/workspace/spine_facts.rb` — What a workspace's stages are judged against: the plan file, the branch against its upstream, the pull request, the review agent and the panes, mapped into {SpineEvaluator::Facts} by the rules of the app's `src/core/spine/facts.ts`, so the CLI and the app read the same facts alike. {#read} makes the live reads for one workspace, each source at most once: the plan file, a few local git calls, one daemon snapshot and one `gh pr view` read in parallel threads, and the open questions. `gh` runs only when it is on the PATH and a declared gate needs it. {#facts_from} is the mapping alone, for a caller that already holds the readings (the snapshot). A source that can't answer leaves its fact nil, so its gates read `unchecked`; nothing here raises.
- `lib/workspace/spine_owner_report.rb` — Records `spine_changed` with `change: "owner_finished"` when the agent that owns a started stage ends its turn, so a reader can show "the stage's agent finished" without watching the pane. Two signals feed it: the agent daemon's Stop hook for a pane ({#turn_ended}), which reports each stage whose `owner` is that pane and that is still `in_progress`, at every turn end; and {SpineWatcher}, which calls {#stage_completed} once when a stage with an owner moves to `completed`. A Stop never reports a completed stage, so a restart of the daemon or a reused pane id cannot report an old completion again. A pane that owns no stage writes nothing.
- `lib/workspace/spine_writer.rb` — Rewrites frontmatter keys of one spine stage file: any set of `status`, `note` and `owner`, plus `updated` and `updated_by` on every write; a status change on a stage that has opted in to a check (it has a `check:` key) also resets `check` and drops the `checked_*` lines. {#verify} writes the check keys alone. It keeps every other byte (line endings, a BOM, comments, unknown keys, lists). The file is read again from its raw bytes each time, since {SpineFile} keeps line spans, not offsets, and the new bytes go out through a temp file in the same folder, an fsync and a rename. The caller serialises writers (`spine set` holds a per-workspace lock); this class also checks that the file did not change between its read and the rename, and starts over once if it did.
