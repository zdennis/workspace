# workspace capabilities

Print what this workspace supports, so a script or the UI can check a feature instead of comparing version numbers.

## Usage

```sh
workspace capabilities [--json]
```

It reads constants, config paths and the `PATH`. It starts no process and touches no state, git, tmux or daemon, so it is cheap to call.

## Options

| Option | Description |
|---|---|
| `--json` | Print one JSON document (below) instead of a readable summary |

## JSON output

```json
{"schema_version":1,"ok":true,"version":"0.27.1",
 "features":{"envelope":1,"error_codes":1,"name_scope":1,"no_input":1,"action_json":1,
   "sessions":2,"locks_json":2,"git_facts":1,"prune_safe":2,"snapshot":6,"events_follow":1,"events_tool_input":1,
   "actions_manifest":0,"agent_send":1,"agent_spawn":1,"spawn_cleanup":2,"focus_pane":1,"focus_cycle":1,"state_done":1,
   "doctor_json":1,"daemon_control":4,"config_json":2,"config_scopes":2,"tmux_show":1,"tasks":1,"event_emitters":2,
   "ui_open":3,"pane_bindings":3,"library":5,"library_play":3,"library_recipes":1,"library_copy":4,"library_installed":1,"instructions":1,"restore":1,
   "workflow":3,"window_state":1,"window_position":1,"cleanup_dry_run":1,"notes":2,"start_packs":2,"start_agent":1,"agent_commands":1,"ahead_of_base":1,"agent_executables":1,"start_plan":1,
   "handoff_auto":2,"handoff_codex":1,"handoff_wait":1,"dev_queue":2,"dev_down_holder":1,"plan":5,"inbox":4,"ask_withdraw":1,"ask_deliver":1,"review":1,"review_patch":1,"add_json":1,"plan_progress":1,"spine_events":2,"spine_eval":3,"spine_verify":1,"spine_start":2,"spine_fanout":1,"spine_check":1,"spine_goal":1,"agent_status":1,"agent_queue":1,"agent_send_interrupt":1,"plan_tasks":3,"agent_hooks":1,"codex_waiting":1,"projects_multi":1,"json_envelope":1,"remove":1,"lifecycle_current":1,"promote":1,"split_cwd":1,"launch_prompt_status":1,"kill_branches":1}, "exit_codes":{"ok":0,"failed":1,"not_submitted":2,"partial":3,"lock_cleared":4,"timeout":75},
 "paths":{"event_log":"/Users/me/.workspace-events.jsonl","hook_events":"/Users/me/.local/state/workspace/.events",
   "run_dir":"/Users/me/.local/workspace/run",
   "library":"/Users/me/.config/workspace/library"},
 "dependencies":{"window_tool":{"path":"/opt/homebrew/bin/window-tool"},
   "gh":{"path":"/opt/homebrew/bin/gh"},"tmux":{"path":null}}}
```

- `features` maps each name to an integer revision. `0` means this CLI doesn't have it, and a name missing from the map means the same. Check `features.no_input >= 1`; don't compare `version`. A revision goes up when the feature's output changes in a way a reader must handle. An older CLI that predates this command answers `Unknown subcommand` (exit 1), so treat that as "no features".
- `exit_codes` names the statuses commands use: `not_submitted` (2, `run`), `partial` (3, `--json` action documents), `lock_cleared` (4, a queued lock wait whose lock was cleared) and `timeout` (75, `--max-wait` ran out).
- `paths` are absolute. `hook_events` is the directory of the agent daemons' hook event files, which [`events`](README.events.md) reads.
- `dependencies` gives the first match on `PATH` for each tool, or `null` when it isn't there. Nothing is run, so there is no version.
