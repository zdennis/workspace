# Workspace CLI

A macOS CLI (Ruby) for managing tmuxinator-based development workspaces in iTerm2.

## Project Structure

- `bin/workspace` — Entry point (4 lines), calls `Workspace.build_cli.run(ARGV)`
- `lib/workspace.rb` — Module root, `build_cli` factory (the streams `output:`, `error_output:`, `input:`, `env:`, and the named overrides `exit_handler:`, `tmux:`, `task_store:`, `skill_source:`, `launchctl:`, `logger:`, each nil builds the real one, for specs); it builds the shared `ScanSlotLimiter`, `RestartRegistry` and `SessionMonitorBuilder` and gives them to `ContextReader` and `Commands::Agent`; error classes
- `lib/workspace/cli.rb` — CLI dispatch, OptionParser definitions, simple command methods
- `lib/workspace/config.rb` — Path constants and configuration
- `lib/workspace/commands/notes.rb` — `notes dir`: the one answer to where a workspace's notes are, through `NotesDir`; `--create` makes the directory and lists it in `info/exclude`; `workspace ui open notes [WS] [--path REL]` sends the person to the Notes view, or one note, through `Commands::Ui` (`workspace-ui://notes/<ws>[/<rel>]`; `--path` is checked by `NotePath.resolve`, refused as `invalid_note_path`)
- `lib/workspace/commands/promote.rb` — `promote [BRANCH] [--name WS] [--dry-run] [--json]`: moves a main checkout's changes and branch commits into a new `.worktrees/<branch>` through `CheckoutMove`, makes it a workspace through `start` (no launch, plan or spine), carries notes through `NotesCarry`, then makes the spine and plan asked for and not carried; refuses `agent_working` (the caller's `$TMUX_PANE` aside); writes `workspace_promoted`; docs in `docs/README.promote.md`
- `lib/workspace/checkout_move.rb` — The git half of `promote`: checks (`plan`, read-only), one tagged stash pinned to `refs/workspace/promote/<id>`, switch, `worktree add`, `stash apply --index` checked against trees recorded before; a failure is undone in reverse (`move_failed`) or kept under the ref (`move_incomplete`); INT, TERM and HUP wait for the step under way through `DeferredSignals`
- `lib/workspace/notes_carry.rb` — Moves `IMPLEMENTATION_PLAN.md` and `spine/` (the old ones renamed `.moved-<time>`) and copies each `--carry-note` into the new notes directory, never over a file; problems are warnings; `.clash?` says whether a copy would land over an existing file (`rename`'s notes check)
- `lib/library/play/promote.md` — The `promote` pack: tell the person what moves, run promote, seed the spine and plan, write `HANDOFF.md`, start the agent, stop
- `lib/workspace/core/` — The lowest layer: the shared rules and tables every other layer may read, and nothing in it depends on anything outside `core/`. Fourteen files: `logger`, `config_schema`, `config_layering`, `config_resolver`, `error_codes`, `duration`, `agent_provider`, `workspace_lineage`, `workspace_name`, `id_patterns`, `file_lock`, `atomic_file`, `locked_json_file`, `agent_protocol` (each described on its own line below)
- `lib/workspace/core/id_patterns.rb` — `IdPatterns`: the name rules shared across sub-systems (`LIBRARY_NAME`, `WORKFLOW_ID`, `WORKFLOW_ID_RULE`); read by `LibraryStore`, `WorkflowDefinition`, `config_schema` and their other readers
- `lib/workspace/core/config_schema.rb` — The one table of config keys: scope, settable, default, value parser, restart flag, doc text; readers, `config set/get/unset` and the docs take their key lists and checks from it
- `lib/workspace/notes_dir.rb` — The one resolver for where a workspace's notes go: its own `notes.dir`, else the directory the project's `notes.default_dir` rule computes, else (a linked worktree) the main checkout workspace's effective notes dir plus the sanitized branch (`tmp/workspace-notes` in the checkout when unset); `config show --json` reports it as `effective_path`; `#path_for(template:, worktree:, root:, workspace:, branch:)` computes the rule's directory for names not yet in use (`rename`'s notes target); `Commands::Notes#info` returns the answer as a Hash (`dir` prints it) and `#files_inside_worktree` counts the files `kill` and `finish` would delete
- `lib/workspace/help_pages.rb` — Data only: the help page of each verb of the commands that share one option parser (`plan`, `daemon`, `workflow`, `library`, `spine`, `binding`, `step`, `review`, `pr`, `ticket`, `goal`, `notes`, `instructions`, `ui`, `projects list`, `projects group`, `config show`), one frozen table per command keyed by verb (`usage`, `summary`, `about`, `options`, `examples`); `HelpPages.render` writes a page and the example separator, `overview_usage`/`overview_verbs` build the bare command's page from the same table, `lookup` finds the longest leading verb; `CLI#verb_help_shown?` prints a page before anything is parsed, and `help_requested?(args, page)` stops at `--` and skips the value of a flag that takes one
- `lib/workspace/config_schema_docs.rb` — Renders the schema into the generated blocks of `docs/README.config.md`; `script/generate-config-docs [--check]` runs it, and a spec fails on drift
- `lib/workspace/state.rb` — JSON-persisted session state
- `lib/workspace/git.rb` — Git and worktree operations; `#path_of`, `#current_branch_name` and `#head_name` (`rev-parse --abbrev-ref HEAD`) are the small reads other classes take as a `git:` seam
- `lib/workspace/name_migration.rb` — Renames a mixed-case workspace (and its worktree workspaces) to lowercase before its agentd starts, under the startup lock: tmux session, configs, run files, state dir, inbox files, state key, marker, tmuxinator config last (held back while any step failed); a failed step is a warning in the daemon log; writes `workspace_renamed`. The steps live in `WorkspaceStoreRename`; `NameMigration` keeps the lowercase decision and the locks. `EnsureAgent` calls `#call` under its startup lock (keyed on the lowercase name); `launch` and a foreground `agentd` call `#call_locked`; `#with_locks(*names)` holds the startup locks of several names (sorted) for `rename`, raising `LockUnavailable`
- `lib/workspace/core/workspace_name.rb` — The workspace name rules: pure class methods `SEPARATOR` (`.worktree-`), `.split` (project and suffix at the first separator, nil without one; same as `WorkspaceLineage.split_worktree_name`, whose callers move later), `.worktree?`, `.project_of`, `.join` (lowercased), `.mixed_case?`, `.normalize`, `.same?`; and the instance that settles a name: `#for_input(name)` is for a name a person typed (the exact name in any case wins, else the one config whose part after `.worktree-` equals it, ignoring case; several are `ambiguous_workspace`; an active workspace with no config keeps its name); `#match` and `#resolve` stay exact, since they also settle names from paths and detection; the CLI's `given_name` is its only caller of `#for_input`
- `lib/workspace/which.rb` — Shared default PATH lookup for injectable `which:` collaborators
- `lib/workspace/doctor.rb` — Dependency checking; warns on a paused plan whose owner pane is working and on a `[~]` task in a workspace with no session; checks the configured command's program on PATH; reports each tmuxinator config whose agent pane runs another command than `agent.commands.<kind>` (`agent-pane-command`), and `--fix` rewrites that pane through `ProjectConfig#rewrite_agent_pane` after a `FileBackup`; checks the skill links (`skills-<harness>` rows) through `Commands::Skills#health`, and `--fix` repairs them through `#repair`
- `lib/workspace/tmux.rb` — Tmux session management; `#capture_screen_styled` reads a pane with its styling (`capture-pane -e`) for `StyledScreen`; `#pane_pid(pane_id)` is the pane process's pid, which `LockHolder` reads through its `tmux:`
- `lib/workspace/styled_screen.rb` — `StyledScreen.parse(raw)`: a styled capture read per character, so `#faint?(line, column)` tells Claude Code's grey suggestion (SGR 2) from a typed draft; `#text` is the plain screen; `#proven?(line)` is false for a line with an escape it could not account for (a shift character, an unknown escape, a reverse-video cell without faint), which leaves only that line unproven and keeps today's refusal
- `lib/workspace/typing_safety.rb` — The one test of whether text may be typed into a pane: the agent's state, an open `AskUserQuestion` (`question_open`), a dialog, and an input line that holds a draft (`input_not_empty`); given a `StyledScreen`, an input drawn entirely faint on every proven line counts as empty; `PromptTyper` and `IdlePromptCheck` go through it
- `lib/workspace/idle_prompt_check.rb` — `IdlePromptCheck#refusal(facts, styled_capture)`: `TypingSafety` plus no busy row (a spinner row, `esc to interrupt`, `Retrying in`) within 16 rows above the input box; nil means the box is empty and nothing is running. `AgentRestart` (as `screen_ready:`) and `WorkflowPanes` read the screen only through it
- `lib/workspace/agent_restart.rb` — The daemon's `restart_agent` worker: waits for a quiet pane, types `/clear` under the delivery lock, confirms it, types the prompt. A moving screen is accepted only on proof the main turn is over (`turn_over:`, `screen_ready:`, held 5s) and then warns that background work may be lost; a Claude Code pane is re-checked under the lock (a draft is `input_not_empty`, a started turn `turn_started`); `run_id:` stops it with `run_unbound` once the pane is no longer bound to that run
- `lib/workspace/project_config.rb` — Tmuxinator config generation
- `lib/workspace/project_catalog.rb` — Groups workspaces into projects (main checkout + worktrees) by the realpath of each checkout's git common dir, read from `.git` files; backs `projects`
- `lib/workspace/project_groups.rb` — Groups of repositories (`group:<slug>` ids), one hand-editable file each at `~/.config/workspace/groups/<slug>.yml`; members keyed by the realpath of the git common dir, at most one group per repository, a gone repository reads `exists: false`; writes under one flock through a temp file and rename; `#group_for_project` is the lookup by project id. `Commands::Groups` is `projects group create|add|list`; `projects stop`/`kill` refuse a `group:` id. `ProjectCatalog` knows nothing of groups
- `lib/workspace/osascript_runner.rb` — Runs one AppleScript through `osascript` with a 5s limit; past it the process group is stopped and the answer is empty with `timed_out`; `ITerm` and `WindowManager#close_window` go through it, and `UiAppProbe` through a second runner set to `osascript -l JavaScript`
- `lib/workspace/ui_app_probe.rb` — The one read-only question to macOS for `ui status`: a frozen JXA script (no input, opens nothing) asks which app would take a `workspace-ui://` link, with its `WorkspaceUILinkRevision`, and which copies are running; `#call` answers `Answer(handler, running, problem)`, and no answer is a `problem`, never an error
- `lib/workspace/commands/ui.rb` — `ui open [VIEW] [WORKSPACE]` builds a `workspace-ui://` link and hands it to `open` (no view means `task`); `ui status [--json]` turns the probe's answer into a read document, reporting a link revision only when the bundle that declares it is the app that would take the link (else null with a `links.reason`), always exit 0
- `lib/workspace/iterm.rb` — iTerm2 session/pane lifecycle (AppleScript); `#last_call_timed_out?` says iTerm2 did not answer, which `stop` turns into a warning
- `lib/workspace/focus_config.rb` — Reads the global `focus.chain` (default `focus + center + dim --opacity 0.5 --duration 3`) into the steps after the first `focus`, as token arrays split on `+`; a value `config set` would refuse, or an unreadable global file, gives the default's steps and a warning, so a bad config never stops `focus`
- `lib/workspace/shell_init.rb` — `ShellInit.text(shell)`: the fixed text `shell-init zsh|bash` prints for an rc file (single-quoted heredocs, nothing interpolated): `wf` (`workflow start` with the default `rpiv` or `WORKSPACE_WF_DEFAULT`), `wfp` (fzf or numbered picker), and the completion for `workspace` and `wf`; docs in `docs/README.shell-init.md`
- `lib/workspace/window_manager.rb` — iTerm2 window operations: find, focus, position, close; `#run_focus_steps` runs a chain's window-tool steps in order, `dim` and `highlight` detached (counted started after 0.25s), the first failure stopping the rest and returned as a `StepFailure`
- `lib/workspace/window_liveness.rb` — Whether iTerm still has each tracked workspace's recorded window (one `live_window_ids` call, none when all are headless); nil for headless or when the list can't be read; backs `window_alive` in `status --json`, `list --liveness --json` and `cleanup`
- `lib/workspace/window_layout.rb` — Window positioning math
- `lib/workspace/json_envelope.rb` — Builds the `--json` action and error documents (`ok`, `code`, `details`, `retry`); the CLI rescue funnel emits the errors, `CLI#run_action` the actions
- `lib/workspace/output_gate.rb` — The stdout every collaborator writes through; `--json` actions divert it to stderr so stdout holds one document
- `lib/workspace/core/error_codes.rb` — Registry of the stable error `code` values, mirrored in `docs/README.json.md`
- `lib/workspace/pane_locator.rb` — Strict pane resolver for `agent-run send`, `focus --pane` and `ask answer --deliver`: only a pane id or `window.pane`, and only a pane of the workspace's own tmux session
- `lib/workspace/pane_bindings.rb` — `bindings.json`: tmux pane id to the run, review or play it works on, with the session it was made in and the `packs` its agent was sent; `session-event` prints it, and the packs composed again, as `additionalContext` on SessionStart; `#move` carries bindings to the panes `restore` resumes in; `#rename_workspace(from:, to:)` rewrites the workspace and session in each binding for `rename`
- `lib/workspace/library_store.rb` — The files of one library scope (`<kind>/<name>.md`, or a `skill/<name>/` directory holding `SKILL.md`; a copy or a symlink), written through a temp file or directory and rename; `renamer:` moves the finished temp entry into place (default `File.rename`)
- `lib/workspace/library.rb` — Resolves a library `REF` across scopes; `#stores` is the one lookup order (project, global, then the built-in store `lib/library/`); `#pack` looks an instruction pack up built-in first; `#play` checks the play `start --play`/`launch --play` point the agent at; `#copyable` checks a `start --agent`/`--skill` entry
- `lib/workspace/recipe_file.rb` — Parses and checks a `recipe` library entry (YAML: `plays`, `packs`, `agents`, `skills`, `agent_kind`, `prompt`, `description`, `workflow`, `workflow_inputs`; `workflow` excludes the list fields and `prompt`, and an input is a String, Integer or boolean turned into a string), listing every problem under `invalid_recipe`; `Library#recipe` reads one, `start --recipe` fills in the flags not given (a recipe with a `workflow` goes to `workflow start` instead and refuses flags it can't use as `recipe_workflow_conflict`), and `library add`/`update` refuse a bad one
- `lib/workspace/library_installer.rb` — Copies a library agent or skill into a checkout's install directory (`.claude/agents/` and `.claude/skills/` unless configured), never over a tracked path, and lists it in the common dir's `info/exclude`; `#install_user` copies to the user-level directory (no git)
- `lib/workspace/library_install_dirs.rb` — The one reader of the `library.install.{skills,agents,user_skills,user_agents}_dir` keys (project over global over default), read when a command runs; `LibraryInstaller` and `Commands::Library` get their directories only from it
- `lib/workspace/instruction_composer.rb` — Builds an agent's instructions from library packs under a heading per pack, and a workflow step's four layers (default packs, workflow, step, attempt); adds the pane's binding after `binding` and the project's `commands.test`/`commands.lint` after `commits`; `#start_packs`/`#compose_start` list and compose what `start` and `launch` send with the first prompt (the automatic `notes` pack, the `dev` pack when the project sets `dev.up`, then `--pack` names; `compose(skip:)` leaves a pack out of a workflow step)
- `lib/workspace/notes_config.rb` — Reads a project's `notes.instructions` (false turns the automatic `notes` pack off for `start` and `launch`)
- `lib/workspace/main_agent.rb` — Which coding agent a project's main agent pane runs (`claude`, `codex`, ..., or `none`), read from the panes of its tmuxinator config; `InstructionComposer` uses it to send the `handoff` pack to Claude Code and Codex only
- `lib/workspace/agent_commands.rb` — Reads `agent.kind` and `agent.commands.<kind>` through `ConfigResolver` (global, project, worktree): the effective agent kind, the command for a kind (default the provider's executable) `#executable_for` (the program that must be on PATH; the global layer alone for a nil workspace), `#names_for`, the program names that count as that agent, and `#aliases_for`/`#detector`; a bad stored value falls back to the default
- `lib/workspace/agent_executables.rb` — Read-only scan of `PATH` for each agent family's launchers (`<exe>` or `<exe>-suffix`, matched whole, never a bare prefix), with `shadowed` paths, configured commands not on PATH, and the `effective` program per kind; capped at 200 rows
- `lib/workspace/commands/agent_executables.rb` — `agent executables [--kind KIND] [--name WS] [--json]`: resolves the workspace, checks the kind (`unknown_agent_kind`), prints text or the `--json` document
- `lib/workspace/agent_command_check.rb` — What `config set agent.commands.<kind>` checks: an absolute path must exist and be an executable file (`agent_command_not_executable`); a bare name not on PATH or off-family is a warning
- `lib/workspace/agent_detector.rb` — `AgentDetector`, one workspace's way to find the coding agent in a pane: `AgentProvider.detect` plus the configured program names as aliases; `AgentCommands#detector` builds it for the session monitor, readiness checks, pane label searches and `restore`
- `lib/workspace/commands_config.rb` — Reads a project's `commands.test` and `commands.lint`
- `lib/library/play/` — The built-in instruction packs (`binding`, `orchestrator`, `commits`, `review`, `notes`, `handoff`, `dev`, `implementation-plan`, `research`, `report`, `plan-review`, `spine`, `promote`), read through `Library#builtin_store`; the `research` pack ends by adding a `note` inbox item (`inbox add --note`) and printing the note link from `ui open notes --path`; the `plan-review` pack reviews the plan, writes `plan-review.md` and posts an inbox item under `plan-review:WS:blocking` or `plan-review:WS:passed`
- `lib/workspace/commands/skills.rb` — `skills install [--install-all] [--dry-run] [--json]` (`confirmation_required` under `--no-input` when it would ask) and `skills uninstall [--dry-run] [--json]` (docs in `docs/README.skills.md`): links the five `lib/skills/<name>` directories into each chosen harness's skills directory (and `~/.agents/skills` when it exists, never created); one question through `Prompt.ask` for the harnesses found and not yet linked or declined (the ones left out are recorded as declined; end of input installs nothing and records nothing; `--install-all` asks nothing and clears declines); exit 1 when anything is refused or failed; codes `skill_path_exists`, `skill_link_foreign`, `skill_link_failed`, `skill_source_worktree`, `skills_source_missing`, `no_harness_found`. `#health` and `#repair` serve `doctor`: one `skills-<harness>` row per harness found and not declined (`ok`, `missing`, `dangling`, `conflict`), and `--fix` links the missing or dangling ones without replacing anything
- `lib/workspace/skill_harnesses.rb` — The four harnesses (Claude Code, Codex, Pi, OpenCode) with their skills directories (`CODEX_HOME` honoured); found by program on PATH or config directory; `~/.agents/skills` only when it exists
- `lib/workspace/skill_source.rb` — Where the links point: the Homebrew `opt` path, else the checkout's realpath; a linked worktree is refused (`skill_source_worktree`, read from `.git` and `commondir` alone, so no HOME, PATH or git call)
- `lib/workspace/skill_links.rb` — Inspects, plans and writes the five links of one skills directory: all five or none, a temp link renamed into place, an identical real directory moved to `skill-backups`, anything else refused with its `mv`; `#ours?` and `#removal_steps` serve `uninstall`
- `lib/workspace/skills_state.rb` — `skills.json` (`{"declined": []}`), flock-guarded through `FileLock` and `AtomicFile` (its own temp name and default file mode), so not `LockedJsonFile`; a corrupt file reads as empty
- `lib/skills/` — The five shipped skills (`workspace`, `workspace-agent-run`, `workspace-inbox`, `workspace-lifecycle`, `workspace-workflow`; each a directory with `SKILL.md`), what `skills install` links; `libexec.install "lib"` in the Homebrew formula ships them
- `script/check-skills` — Checks the skill files in `lib/skills` against the real CLI: each command, subcommand and `--flag` against `--help` (run in an empty temp HOME) and each error code against `error_codes.rb`; exit 1 on a mismatch
- `lib/workspace/commands/rename.rb` — `rename [WS] NEW [--name WS] [--dry-run] [--json]`: renames a stopped worktree workspace's branch, directory, name and session; `RenamePlan` first, then under `NameMigration#with_locks` and `DeferredSignals` the git steps (worktree move, branch rename; undone in reverse, `rename_failed`), then forward-only steps through `WorkspaceStoreRename`, notes, tasks, inbox, ledger and bindings, journal deleted, then `workspace_renamed` written (a failed delete keeps the journal and writes no event, so the re-run writes it once); a failure in any step keeps the journal (`rename_incomplete`) and the same command finishes it; launches nothing
- `lib/workspace/rename_plan.rb` — The read-only half of `rename`: the new names (as `start` makes them), the notes move (`move`, `with_checkout`, `stays`) and every refusal (`workspace_running`, `run_active`, `dev_lock_held`, `rename_*`); `resume: true` reads names and the notes decision from the journal and skips what the finished steps would trip; writes nothing
- `lib/workspace/rename_journal.rb` — One file per old workspace name, written before the first git step and deleted after the last; `#read` finds it by the old or the new name (`rename_in_progress` when unreadable)
- `lib/workspace/workspace_store_rename.rb` — Renames what is keyed on a workspace's name: tmux session, settings, run files, state dir, inbox files, state key, marker and last the tmuxinator config (held back while a step failed); a failed step is a warning and a retry finishes it; names checked against directory listings, a case-only change through a temporary name; shared by `NameMigration` and `rename`
- `lib/workspace/deferred_signals.rb` — `#hold { }` holds INT, TERM and HUP while steps run; `#caught` is asked between steps, `#report` names the signal in the error raised, `#note` takes one that arrived as an exception; an unreported one is sent again after the old handlers are back
- `lib/workspace/commands/agent.rb` — The agent daemon's command object; `#handle(message, client = nil)` is public (the socket protocol's one entry, which specs call instead of a private dispatch)
- `lib/workspace/commands/` — Complex command objects (launch, kill, focus, start, agent, ensure_agent, lock, dev, notes, plan, pull_request, rebase, push, projects, capabilities, send, review, restore, snapshot, daemon, ui, binding, library, instructions, workflow, skills, rename)
- `lib/workspace/notes_setup.rb` — Fixes a new worktree's notes directory for `start` and `add`: writes the computed path as the worktree's own `notes.dir` (never over an existing value), makes the directory and its `info/exclude` line; every problem comes back as a warning, never an error
- `lib/workspace/spine_file.rb` — One spine file (a stage file or `goal.md`) read without following links, never failing: `PlanFile`'s frontmatter dialect plus `[a, b]` and indented `- a` lists, status aliases to the six canonical values, the `## Done when` checklist, `revision` (short SHA-256 of all bytes), `key_span`/`frontmatter_lines` for `spine set`, `check` (the opt-in and verdict that `spine verify` writes), warnings with codes
- `lib/workspace/spine_tree.rb` — Walks `spine/` in the notes dir (`<number>-<id>.md` stages, a folder named like a stage file for sub-stages, to 3 levels; the 64/24/96 limits); `Stage` holds the file, children, `rollup` and the dependency checks; `#find(path)`, `#to_h` is the `spine show --json` document
- `lib/workspace/spine_rollup.rb` — The one roll-up of a stage's children (`model.ts` `rollUp`) over each child's effective state (a folder-only child takes its own roll-up): `status` (all skipped is `skipped`), `done`, `total`, `counts` with `disputed`; `SpineTree::Stage#rollup` calls it
- `lib/workspace/commands/spine.rb` — `spine show [WS] [--name WS] [--json]`: the notes dir through `Commands::Notes#info`, then `SpineTree`; read-only, a bad file is a warning, never an error; `#stage!` and `#write_one` (one write under the spine lock, after a caller check) serve `spine start`
- `lib/workspace/spine_inferred.rb` — Port of the app's `inferred.ts`: with no `spine/`, `spine show --evaluate` lists Research to Ship (Ship for a linked worktree) under `inferred`, from the plan, the workspace's runs still going (a run with a research/plan/implement/verify step outranks the plan), the review agent and the pull request; `.stages` is the pure rules, `#infer` adds the run files and the checkout layout to `SpineFacts`' one read
- `lib/workspace/commands/spine_start.rb` — `spine start [WS] PATH [--pane P \| --spawn KIND] [--play REF] [--if-revision REV]`: refuses from the file (`stage_done`, `stage_waiting` by file statuses, `stale_revision`) and the panes (`stage_owned`, `pane_busy`) through `PaneDispatch`, then writes `in_progress` and the owner under the spine lock, types the brief (play, `spine` pack, stage path and file), binds the pane; only a failed delivery leaves the file written, with a reset hint
- `lib/workspace/plan_file.rb` — The parser for a workspace's `IMPLEMENTATION_PLAN.md` (`PlanFile.parse(text)`, `PlanFile.read(path)`; nil when the file is missing): frontmatter, the `- [S] ID Title` tasks under `## Tasks`, `counts`, `percent`, `current`, `warnings`; it never fails. `PlanFile.set_status`, `.set_owner_pane` and `.set_task` are the only writers of the file: one frontmatter line, or one task line's box and `<!-- owner: %N -->` comment, through a temp file and rename, with one re-read and retry
- `lib/workspace/plan_state.rb` — `PlanState#derive` picks the one plan `state` (`empty`, `done`, `paused`, `stopped`, `waiting`, `working`, `blocked`, `stalled`, `idle`) from the parsed plan and the facts; `#row` builds the row `plan status --json` and, minus `tasks`, each member's `plan` in `snapshot` (from the snapshot's own reads)
- `lib/workspace/plan_config.rb` — Reads a project's `plan.stall_seconds`
- `lib/workspace/start_ref.rb` — What `start` and `ticket show` make of a ref (JIRA key or URL, pull request, issue, branch): its `kind`, `key` and `branch` (`#call(input, root:, names:)` picks the lowercase key for a JIRA ref, else the existing branch that matches it without case, local names first), and `#project` for the project a worktree would join (the parent repo from inside a linked worktree)

## Conventions

- Follow existing code style (methods, snake_case, minimal abstraction)
- Composition over inheritance, no modules for private method grouping
- Command objects receive parsed values, never ARGV
- Only `CLI#run` calls `exit`; everything else raises `Workspace::Error` or `Workspace::UsageError`
- IO injection: classes accept `output:`, `error_output:`, `input:` for testability
- YARD docs on all public classes and methods
- Tests use RSpec, run with `bundle exec rspec`. Serial is the default and the pre-commit gate.
- For per-commit gating do NOT run the full suite — it takes too long. Run only the targeted spec files that were changed or are obviously impacted, plus `bundle exec standardrb lib/ spec/`. Use `script/parallel-spec` or the full serial suite only when a whole-suite run is explicitly asked for.
- `script/parallel-spec [ARGS...]` runs the suite in parallel with parallel_tests (one process per performance core; about 44s against 232s serial). Each process gets its own short `HOME` and `XDG_*` directory under `/tmp`, and SimpleCov results merge into `coverage/`. Only a whole-suite run (no arguments) uses and refreshes the timings in `tmp/parallel_runtime_rspec.log` (untracked); with arguments, or before a log exists, files are grouped by size. Extra arguments go to `parallel_rspec`.
- Lint with `bundle exec standardrb lib/ spec/`
- `bin/` is for project executables (the public interface) — only `bin/workspace` belongs here
- `script/` is for project-specific dev scripts and tooling (e.g., test helpers, one-off utilities)

### Test organization

Every spec sits in one tier directory, which mirrors `lib/`: `spec/unit/workspace/...`, `spec/integration/workspace/...` or `spec/system/workspace/...` (a spec of the spec tooling itself, such as `spec/unit/spawn_guard_spec.rb`, sits directly under its tier). `spec_helper.rb`, `spec/support/` and `spec/fixtures/` are shared and stay at the top of `spec/`. Reach repo files through `PROJECT_ROOT` (set in `spec_helper.rb`), never through `__dir__`, so a spec can move between tiers.

Shared fakes of the adapters live in `spec/support/fakes/`: `FakeTmux` (for `Tmux`; it replaced `CLITestHelpers::FakeTmux` and the per-spec restart, liveness and sentinel tmux fakes) and `FakeGit` (for `Git`). `spec/unit/fake_contract_spec.rb` holds each to its real class by the accepts-every-call rule in `spec/support/fake_contract.rb` (same required positionals, every real keyword accepted by name or `**`, nothing extra required); a section that adds a shared fake adds one `describe` block there.

Place a new spec by the first rule that fits:

1. It starts any process (`system`, backticks, `Open3`, `spawn`, `fork`, `IO.popen`, `PTY.spawn`, a real `git`, `tmux`, `osascript`, `ruby`, `sh`), even once or from a thread: **system**.
2. It wires two or more real Workspace classes that each have behaviour (a command object over a real tmpdir-backed store, the CLI over real collaborators): **integration**.
   A spec whose collaborators are all doubles, fakes or plain value objects is not integration: when in doubt between the two, pick unit.
3. Otherwise, one class with doubles, fakes or injected runners: **unit**. Unit specs must be fast.

- Temporary directories are not external: unit and integration specs may read and write under `Dir.mktmpdir`.
- A stubbed process call (`allow(Open3).to receive(...)`, an injected runner lambda) starts nothing and is fine in any tier. `and_call_original` on a process call does start one, so that spec is system.
- When a unit-shaped spec needs a few examples that start a process, put those examples in a separate file under `spec/system/` instead of moving the whole file.
- A helper that memoizes a fixture built by running git, such as `RepoTemplate` in `spec/support/repo_template.rb`, is for system specs only: whether it spawns depends on which spec asked first.
- Run one tier with `bundle exec rspec spec/unit` (seconds), `spec/integration`, or `spec/system`. The whole suite is still the pre-commit gate.

`spec/support/spawn_guard.rb` enforces the rule. The tier comes from the directory as `type:` metadata, and a `type:` written on a group wins. In a unit or integration example every spawn point is blocked (`SpawnGuard::Violation`, an `Exception`, so `rescue => e` does not catch it) and recorded, and the example fails afterwards even if the code under test caught it with `rescue Exception`. Threads the example starts are checked too. Spawns at load time, in `before(:context)`, or in a thread that outlives its example are not checked, so do not write them. A spec that trips the guard moves to `spec/system/`; there are no exemptions.

## Orchestration

The main interactive session is an **orchestrator**, not an implementer. Its job is
to hold the plan, decide what happens next, and report results — not to read every
file itself. Delegate the work to sub-agents via the Agent tool, and keep the
conversation for decisions the user needs to make.

Delegate when a task means reading across several files, running a broad search,
reviewing a diff, or doing work that is independent of other work in flight. Launch
independent agents in a single message so they run concurrently. Do not delegate a
single-fact lookup when the file and symbol are already known — that costs more than
it saves.

### Choose the model deliberately

Pass `model:` on every Agent call. The default is not always right, and an
oversized model on a mechanical task is pure cost.

- **haiku** — mechanical and well-specified: file lookups, running a known command,
  collecting output, simple edits with an exact target.
- **sonnet** — the default for real work: implementing a described change, writing
  tests, focused review, multi-file search that needs judgment.
- **opus** — reserve for genuine difficulty: architecture decisions, subtle
  debugging, work where being wrong is expensive and hard to detect.

Balance cost against the value of the answer. Most delegated work is sonnet; reach
for opus when the task is hard, not when it is important.

### Agents must be terse

Instruct every sub-agent to report only the essentials. A sub-agent's response
should be the conclusion and the evidence needed to trust it — nothing else.

- No preamble, no restating the task, no narration of what it is about to do.
- No file dumps. Cite `file_path:line_number` instead of pasting the code.
- No summary of work already described. If it changed three files, say which three
  and what changed, in one line each.
- Report failures plainly, with the error, rather than describing the attempt.

Put this instruction in the agent's prompt. The orchestrator relays what matters to
the user; a verbose sub-agent report is cost paid for context the user never sees.

## Analysis and Research Output (Pyramid Principle)

When performing analysis, evaluation, or research — whether directly or via agent teams — always structure output using the Pyramid Principle (Barbara Minto):

1. **Lead with the answer.** State the verdict/recommendation in 1-2 sentences at the very top.
2. **Follow with a compact recommendation list.** Actionable items, ordered by value, before any supporting detail.
3. **Then provide the detailed analysis.** Supporting evidence, trade-offs, and methodology come after the recommendations.

The reader should be able to stop reading after the first two sections and have the full picture. Details are there for those who want to dive deeper.

This applies to: architecture reviews, agent team reports, research notes, Obsidian project notes, and any written analysis saved to files.

## Pre-commit Requirements
